## 1. 三类证据

| 证据 | 方法 | 不能代替 |
|---|---|---|
| 内部模型正确性 | 手算、独立小参考、不变量、负向测试 | 与真实硬件的精度校准 |
| 恢复等价性 | 连续执行与新进程恢复对照 | 对同一错误模型的独立正确性验证 |
| 执行性能 | 固定语义、输入和环境的 wall time/内存测量 | 模型吞吐或 IPC |

不以平均延迟相同替代逐事务正确性，不把恢复成功退出当作完整 checkpoint 验收。

## 2. 连续运行与恢复对照

```text
A：从头连续运行到终点，不保存
B：运行到 K，保存，原进程继续到终点
C：全新进程加载 K，运行到同一终点
```

- A 与 B 的模型轨迹一致：保存本身没有扰动业务。
- B 在 K 后的轨迹与 C 一致：恢复保留未来行为。
- 终态、事务集合、资源账本、累计统计一致。
- 重复进行 C → 保存 K2 → 新进程恢复，验证绝对逻辑时间、时钟相位和身份不漂移。

首版建议固定环境下规范化轨迹全序一致；关键字段为逻辑时间、阶段、事务身份、资源变化和仲裁/完成顺序。宿主地址、进程号、文件路径及 wall time 不纳入模型等价字段。

摘要用于快速定位，不替代规范化记录比较。发现不一致时报告第一处分歧及相关事务、组件状态、未来事件与输入位置。浮点容差如有必要，需事前逐指标规定，不得用于掩盖丢事务、错顺序或错时刻。

## 3. 最小验证矩阵

| 用例 | 验证点 | 对应契约 |
|---|---|---|
| 单请求无竞争 | 接纳、服务、返回与完成时间可手算 | TIME、RES |
| 真实数据读写 | 按已确认 Q2 冲突顺序、执行取值规则和 fail-fast 访问检查，用独立参考核对数据与拒绝行为 | MEM-SEM、ENG-01 |
| 在途读写保存 | 写入前后及读响应在途切点恢复后，内存内容、读值和写提交次数一致 | MOD-02、checkpoint 数据清单 |
| 双源共享资源 | 容量不超分配，仲裁政策可复现 | RES-04、TIME-04 |
| Credit 耗尽 | 不再发送，新许可可见后恢复 | RES-03/05 |
| 在途 credit 保存 | 槽位已释放不等于发送者已有额度 | RES-05、checkpoint 状态清单 |
| 队满/响应阻塞保存 | 不靠排空避开拥塞现场 | MOD-02、checkpoint 切面 |
| 服务完成事件未到 | 剩余时长与截止时间正确 | EVT-01、TIME-02 |
| 同刻到达/返回/timeout | 符合冻结的可见性和裁决规则 | TIME-04 |
| 取消及对象回收 | ID 不复用，旧句柄不能命中新对象或双重释放 | EVT-03/04/09/10 |
| 随机输入/trace 中点 | 输入游标和随机状态恢复一致 | OBS-01/02 |
| ROI 中间保存 | 跨窗事务、面积和直方图不重复累计 | OBS-04/05 |
| 多次恢复再保存 | 时间、事件序号、引用关系不漂移 | TIME、EVT |
| 首版双时钟与有理数恢复 | 原相位、累计余数和下个合法边沿不变 | TIME-03 |
| 损坏/截断/未发布文件 | 拒绝进入运行并报告原因 | ENG-01 |
| 错版本/输入/配置 | 明确拒绝，不猜默认状态 | MOD-06、checkpoint 兼容 |
| 不可恢复组件 | 保存前报告不支持的组合 | MOD-05 |
| 无事件但事务未结束 | 报告异常，不伪装成功 | ENG-02 |

ID 不复用与宿主槽位复用的负向测试不等于完整硬件 reset 验证；首版仍未批准局部 reset 流程。

C36 确认替换运行时，不替代原模型验收。以下内核测试按 [09](./09_discrete_event_kernel.md) 的最终接口细化后实施：

| KERN-17 | 当前激活 Selected 时新增下一阶段/下一拍需求，保留到后续；当前评估结束不能清掉新需求，多次恢复保持次序 |
| KERN-18 | 源完成在第四阶段提交，第五阶段未清理的最终超时检查 Selected 后读取完成状态并成功结束；不要求撤销检查，不新增事务回滚 |
| KERN-19 | 阶段入口全部事件先转 Selected，再调用 handler；A 不能取消同阶段尚未调用的 B，不因回调顺序改变取消资格 |
| KERN-20 | 后续未开始阶段的合法 Queued 动作可取消/改期；不因进入同一时刻被过早锁定 |
| KERN-21 | 新增/改期到当前或已结束阶段明确报错，原合法安排不被静默破坏；无追加批次、无隐式 1 ps 修正 |
| KERN-22 | 到期收集可安排本拍后续评估，评估可产生提交候选；新 credit 在提交后只触发下一合法本域边沿评估，不同拍旁路 |
| KERN-23 | 仲裁与提交先完整裁决再更新；不允许仲裁回调通过新建当前阶段事件进行提交，不由组件遍历顺序超分配资源 |
| KERN-24 | 空阶段逻辑越过后不能重开；无工作不要求真实事件或全组件扫描；全部时钟域共享阶段顺序 |
| KERN-25 | 第六阶段保存前确认前五阶段已结算；恢复不重复前态样本、完成/timeout 检查，不将业务 Selected 恢复为可取消状态 |
| KERN-26 | 多个活动使用者依次释放时，只有本对象责任终结且最后使用者结束后才回收；出堆、取消或 handler 返回不能提前销毁仍被使用的数据 |
| KERN-27 | 本地发送结束释放响应槽后，CDC/接收消费仍能访问 payload；最后拥有者结束才回收，资源槽释放与数据寿命不混淆 |
| KERN-28 | 父事务完成并回收后，独立 credit 返回记录继续正确归还额度；不漏回、不重复归还，也不无必要地强留事务 |
| KERN-29 | 复用已释放宿主存储创建新对象时分配新 ID；旧句柄明确失败，不命中新对象，不依赖无限终态历史表 |
| KERN-30 | 在终态但仍有使用者、所有使用者已释放、父事务释放但 credit 在途三类切点保存/恢复；拥有关系、回收结果与编号后缀和连续运行一致 |
| KERN-31 | 真改期、取消、对象回收与多次恢复后，版本与排序进度不倒退；已用排序不重新分配给新安排；计数耗尽明确失败、不回绕 |
| KERN-32 | 长序列结束并排空所有责任后，活动记录回到预期基线；编号继续增长但记录不随历史总数无界增长，日志/弱句柄不永久阻止回收 |
| KERN-33 | 未完成责任的拥有引用目标丢失时拒绝恢复；合法失效弱句柄与纯诊断 ID 不复活对象，使用弱句柄访问已回收对象时明确失败 |
| KERN-34 | 同一对象分别被 OwnerRef、Handle、ID 关联时，仅拥有引用阻止回收；责任已终结且最后拥有者释放后，残留弱句柄/标签不阻止回收 |
| KERN-35 | 活对象的弱句柄仅在解析与适用版本、权限、状态校验通过后允许操作；持有 ID 或 OwnerRef 不自动获得修改权限 |
| KERN-36 | 同一对象的多个拥有关系恢复后仍指向唯一对象，保活责任不丢失；Handle/ID 不被提升为拥有关系，拥有引用不被降为弱关系 |
| KERN-37 | 连续运行与恢复运行中，未授权的取消/改期均明确拒绝；对象仍活着或解析成功不能绕过版本及 Selected 锁定规则 |
| KERN-38 | 接收候选通过但未提交时仍由原队列负责；成功提交才交接，不重复消费；入队后必要共享不产生额外消息或硬件占用 |
| KERN-39 | 下游拒绝/背压时原队列顺序、消息和拥有关系保留；无额外 credit 扣减、接收占槽或成功计数，候选预留不泄漏 |
| KERN-40 | 响应发送启动交接 payload 后，本地响应池仍占槽至发送结束；后续 CDC 保活数据，不因 shared_ptr 移动提前释放资源 |
| KERN-41 | 增减合法临时强引用不改变业务完成、权限或 credit 轨迹；完成状态不依赖 use_count，最后必要拥有者释放后正确销毁一次 |
| KERN-42 | 共享对象恢复后使用同一对象/控制块；临时装载强根解除，不使对象长期多一个拥有者；已回收弱目标不复活 |
| KERN-43 | 在成功交接、失败保留和共享在途切点比较 A/B/C：拥有关系、资源账本及规范化后缀一致，不恢复半交接状态 |
| KERN-44 | 源完成并移除 outstanding，但未取消的超时检查仍保活原事务；到期读终态判成功且不重复计数，结束后释放该拥有责任 |
| KERN-45 | 检查仍 Queued 时合法取消可解除其事务拥有责任；Selected 检查不可取消，持有原事务直至使用结束，无反向强引用环 |
| KERN-46 | 在事务完成而检查未执行的切点保存/恢复：原事务及检查共享关系、弱回指、deadline 不变，后续释放和规范化轨迹与连续运行一致 |
| OBS-TEST-01 | 响应池本拍由满转有空槽，周期诊断快照看前态，提交后 checkpoint 看后态；恢复不重复切点前态样本 |
| OBS-TEST-02 | 占用 2 从 0 持续至 10 ns，在 10 ns 变为 1，持续至 15 ns；积分为 25 slot·ns，与采样频率/同刻事件数无关，恢复累计相同 |

C37–C52 已确认调度、生命周期、引用、交接、shared_ptr 及超时保活原事务；余项按 C53 分组，内部无语义变化的细节不再逐项要求用户批准。相关测试据最终外部契约细化；上述均为计划，不是已运行测试。

C53 的阶段门槛不降低验收：A 获批并明确授权后可实施基础模块与对应内核单测；首个端到端闭环仍须先冻结 B/C/D 最小规范，再证明双域有理数、有限资源、真实读写及 A/B/C 在途恢复一致。P3 扩展诊断前，P1 必须已有支撑轨迹对照的最小观测，不把 checkpoint 延后到全模型完成。

读写子矩阵见 [06 的 MEM-01 至 MEM-12](./06_memory_transaction_contract.md#10-验收案例)，覆盖 RAW/WAR/WAW、区间重叠、非冲突乱序、写已生效未确认和读已采样未交付。参考检查既要重建字节内存，也要独立检查冲突提交顺序；不能只顺着被测实现的提交记录重放并比较最终值。

| RSP-04 | 池中已有两条响应时可无缝接续，接续只使用原持有槽；池容量为 1 时不能借刚释放槽同拍生成下一响应 |
| SRC-01 | 两源 U 分别配置，默认各 1；每拍仅消费 min(U, 边沿前队列长度)，新到响应不旁路；每条完成和 credit 返回恰好一次 |
| SRC-02 | 消费宽度为 0、负数或非整数明确报错；恢复不改变 U 或接收 FIFO 顺序 |
| SVC-06 | L=1 在 k+1 最早提交，L=0/负数/非整数被拒绝；响应满时恢复后等待空间，不重新计时 |
| SVC-07 | II=3、边沿 10 启动、13 阻塞、14 成功时下一次最早 17；失败尝试不更新计数，保存恢复保持下一资格边沿 |

上述用例是首版范围；不是已运行结果。共享池、发送结束释放、可配置 U 与 L/II 计数均按本轮确认行为覆盖；容量和延迟数值基线仍待冻结。

故障注入计划包括丢失/重复事件、重复 credit 返回、破坏引用、写文件中断；它们用于测试检查器是否真正发现问题，不是正常业务模式。

## 4. 性能实验

### 4.1 两套时间和指标分别报告

模型指标：事务/simulated-second、有效 bytes/simulated-second、端到端/分段延迟、队列占用和每流完成情况。

宿主指标：

- 完成固定工作量的 wall time、CPU time、峰值内存。
- 逻辑动作数量、内核派发与组件激活次数、每完成事务的调度次数。
- 事件日历峰值、取消/改期频率、位置索引维护成本、激活合并率和候选评估次数；不再计量 SystemC 唤醒或以惰性节点清理为首版机制。
- Trace 开关与详细级别的独立成本。
- 保存暂停、文件大小、恢复时间、保存额外峰值内存。
- 编译模式、版本、宿主、输入、seed、配置与重复次数。

不预设事件/s 或加速倍数门槛，规模与预算由 Q9 确认。

### 4.2 工作负载矩阵

| 类型 | 观察目的 |
|---|---|
| 稀疏/长空闲 | 空闲跳过是否有效，是否漏掉定时事件 |
| 单源持续饱和 | 服务/链路瓶颈与事件成本 |
| 多源竞争 | 仲裁成本、公平性和资源反馈 |
| 长服务延迟 | 是否用定时事件代替无效轮询 |
| 频繁背压 | 重复唤醒和无进展派发成本 |
| 多个合法切点保存 | 快照大小及现场复杂度对成本的影响 |
| 双域频率比与 CDC | 量化/跨域等待对时延的影响，以及是否避免空边沿轮询 |
| 响应背压与混合消息大小 | ready-but-uncommitted 占槽、消息公平与字节吞吐的区别 |

### 4.3 优化验收

相同模型、输入、日志级别和统计边界下比较基线与优化版本。对普通等价优化，先验证轨迹与终态一致，再测性能。重复试验报告分布，不只挑最快一次。

将“开启 checkpoint 能力但不保存”“执行保存”“恢复后运行”分开测量。独立报告保存成本，不能通过排除某一版本的 I/O 来制造加速。

固定工作量完成时间与固定模拟窗口吞吐不得混用。ROI 结束后的 drain 是否改变竞争条件，按实验契约明确记录。

## 5. 输出与放行规则

建议每次实验保留运行 manifest、最终生效配置、结果摘要、可选规范化 trace 和失败诊断。恢复运行单独标注父 checkpoint 身份。

候选放行条件：

1. 相关单测、负向测试与集成测试通过。
2. 选定拥塞中间态通过 A/B/C 恢复对照。
3. 不变量在正常路径及故障注入下有效。
4. 性能优化提供相同语义的对照数据。
5. 新组件增加独立可恢复性测试。

当前没有模拟器实现，因此本文件不记录“测试通过”“性能达标”或硬件精度结论。
