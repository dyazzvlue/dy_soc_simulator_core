## 1. 已确认语义

保存有在途事务的状态；在规定提交边界生成 checkpoint；新进程恢复后，规定的模型可观察后续轨迹与连续执行一致。

不要求任意 C++ 指令处冻结，不保存任意 `SC_THREAD` 栈，也不把进程内存镜像当作默认快照格式。所选 SystemC 版本的时间和暂停 API 行为必须在实现阶段核实。

下面的切面、文件与恢复算法是为实现该目标提出的方案，尚待细化批准。

## 2. 保存边界

安全提交边界不是空闲点，也不是 drain：

- 当前 handler 已返回，模型阶段更新完整提交。
- 没有未记录的跨组件副作用或局部超前时间。
- 全部未来影响存在于组件状态或有权威归属的事件记录中。
- 依据 Q3 的双域统一提交行为，初版建议在同刻所有时钟域提交、完成/超时诊断与统计结算后保存；不能截在一个域已提交、另一个域尚未提交的中间。具体 phase/触发仍归 Q6。
- SystemC 的未处理内部通知不能携带唯一业务状态。恢复时应由权威记录重建唤醒。

保存申请若发生在边界之间，记录“申请时间”和“实际切点”，在下一个合法边界保存，不声称捕获了原申请瞬间。

允许请求在链路中、队列满、服务未完成、响应阻塞或 credit 返回在途。不能为了简化保存偷偷推进到所有事务完成。

如果零时间活动无法收敛到合法边界，应诊断失败而不是无限等待；上限和错误报告需定义。

## 3. 状态清单

| 类别 | 必需信息 | 漏存后果 |
|---|---|---|
| Manifest | 完成标识、schema/模型版本、配置和输入摘要、构建身份 | 文件可读但语义不兼容 |
| 时间 | 逻辑切点、1 ps 网格、阶段约定、两域有理数周期/原相位、边沿序号或等价余数 | 截止时间或采样边沿漂移 |
| 对象 | 稳定 ID、类型、版本和引用关系 | 对象错连或共享关系丢失 |
| 事务 | 状态、代际、依赖、终结条件、时间戳 | 丢失责任或重复完成 |
| 资源 | 队列顺序、预留、占用、仲裁位置、credit | 恢复后容量或公平性变化 |
| 动作 | 到达/完成/返回/timeout，排序及有效性 | 丢动作或重复动作 |
| 输入与随机 | 内容身份、游标、发生器内部状态 | 恢复后输入不同 |
| 统计 | 计数、面积、直方图、上次结算点、ROI | 重复累计或跨窗偏差 |
| 输出 | 运行分支和已提交前缀身份 | 恢复后重复拼接输出 |
| 数据内容 | 按已确认 Q1 保存内存与在途读写 payload，记录必要的可见性/提交状态 | 时序相同但读取值错误，或恢复后重复执行写入 |
| 双向传输与 CDC | 当前整消息、发送起止边沿、同步进度/可见时刻、方向及所属接收配额 | 重发、提前接收或重复消耗 credit |
| 仲裁与服务 | 两向 RR、响应分组顺序、下一允许启动边沿、服务到期点、ready-but-uncommitted | 公平性漂移，或把到期但受阻的读写错误执行 |
| Timeout | 原 deadline、固定 G、最终边沿/时刻、宽限状态和计数 | 恢复后重新赠送宽限或误报超时 |

[Q2](./06_memory_transaction_contract.md#8-checkpoint-必须保留什么)确认后，数据状态必须区分“未执行”“已执行待响应”和“源端完成”。保存目标接纳顺序、下一顺序号及冲突关系的权威信息。已执行写不能重做，已固定读响应不能从当前 RAM 重新取值；冷启动清零不得在装载后覆盖恢复内容。

仅比较最终 RAM 不足以发现重复执行同值写；同时比较执行提交身份、次数和响应轨迹。

[Q3](./07_time_clock_cdc_and_timeout.md) 和 [Q4](./08_interconnect_and_memory_service.md)要求额外覆盖：服务到期但响应满时仍占服务槽，读尚未采样、写尚未更新；保存该状态不能通过排空或提前生成结果化简。记录每池 C/F/Q/R 及其消息/返回动作来源，恢复不重新初始化满额 credit。

已预定的链路接续边界也要恢复一致：不能因重建唤醒插入一拍，也不能把切点新返回的 credit 提前使用。C29/C30 已确认本地共享响应池包括正在发送者，必须保存空槽、各源排队顺序与当前发送占用；整条发送结束才释放，不凭恢复过程增加发送暂存容量。

C31–C35 进一步要求保存方向发送序号/下一序号，以恢复同边沿 CDC 批量登记的接纳顺序；记录每源消费宽度 U 的配置身份；恢复原服务到期点及上次实际启动/等价的下一允许启动边沿。II 不是固定周期窗口，失败的启动尝试不改变计数。单次批量登记与消费在统一提交切面内完成，不保存未记账的半个批次。

可重建派生字段必须标明重建规则，并验证与保存的权威状态一致。不能只存 credit 计数而漏存相关 buffer、在途配额和返回动作。

对取消事件，可以保存失效信息或规范化清除，但必须保持未来行为、序号和所有权正确。清除 tombstone 不等于释放其关联事务的全部资源。

## 4. 保存流程与文件发布

候选流程：

```text
接受保存申请
 -> 到达合法提交边界
 -> 暂停模型派发，不推进模拟时间
 -> 检查组件能力和资源不变量
 -> 结算切点处统计并构造一致快照
 -> 写临时目标、校验内容
 -> 发布完整 checkpoint
 -> 继续原运行或按用户要求退出
```

建议首版同步完整快照；不引入需要写时复制的并发后台保存。

文件格式尚未决定。无论最终使用单文件还是目录包，都要求：

- 未完成写入不能被当成有效快照。
- 清楚区分版本/配置兼容校验和文件完整性校验。
- 发布过程有失败语义，不能覆盖唯一可用快照后才发现写入失败。
- 进程中断测试与机器掉电耐久性是不同保证。原子重命名不单独保证掉电后数据持久，是否要求 `fsync`/目录持久化应按平台另行定义。
- 保存失败必须显式报告；是否继续原运行由策略确定，不能生成成功标记。

首版建议同环境严格恢复。校验和不提供来源认证；加载器仍需检查长度、计数、容量、引用、时间范围和未知类型，避免把损坏内容当合法模型。

## 5. 新进程恢复

候选顺序：

1. 验证完成标识、格式、兼容身份、输入和配置。
2. 创建固定组件结构和稳定 ID 注册表，不安排业务事件。
3. 载入对象自身状态，不依赖其他对象已完成装载。
4. 解析引用、共享 payload 和事务关联。
5. 恢复事件、随机状态、输入游标和观测状态。
6. 检查守恒、容量、合法阶段和所有截止时间。
7. 设置逻辑时间映射、时钟相位并重建唯一的 SystemC 唤醒。
8. 从指定逻辑阶段继续执行。

失败时不进入半恢复运行。

### 逻辑时间映射

建议恢复进程采用：

```text
logical_now = checkpoint_base + SystemC_elapsed_since_restore_origin
```

原运行的切点是 100 ns，动作截止 140 ns，则恢复后的相对等待为 40 ns，日志仍记录 140 ns。不得把绝对 140 ns 当成剩余时长。

反复保存恢复时，新切点仍使用统一的逻辑时间；不能重复叠加历史基点。局部边沿按原相位和累计有理数周期计算，不能在恢复时重置余数或重新启动零相位时钟。服务、CDC 和 timeout 都继续等待原到期点，不能重跑完整延迟或重新赠送宽限期。

到期时间等于切点的动作如何处理，必须依赖保存阶段契约决定，不能靠“时间不早于当前”一条检查放行。

## 6. 兼容性与扩展

首版建议锁定模型版本、schema、语义配置、输入与运行环境。文件能解析不代表可以恢复。

以下需独立设计，不能作为普通恢复：

- 修改 buffer 容量、路由、时钟、地址映射。
- 改换精度模型，或从 detailed 切换到近似模型。
- 将旧 schema 自动补字段后继续执行。
- 多宿主线程/分区之间迁移。

未来实验分支可以允许经过验证的参数修改，但应声明是否需要排空、状态映射和重新预热，不承诺与原运行逐事件一致。

Checkpoint 和 record/replay 也不同：首版建议受控离线输入；将来接实时外部输入时需记录值和注入位置。不可回滚的真实外部副作用不能靠恢复内部状态撤销。
