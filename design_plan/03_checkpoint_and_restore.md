## 1. 已确认语义

保存有在途事务的状态；在规定提交边界生成 checkpoint；新进程恢复后，规定的模型可观察后续轨迹与连续执行一致。

不要求任意 C++ 指令处冻结，不保存挂起线程栈或协程帧，也不把进程内存镜像当作默认快照格式。C36 已确认首版改用纯 C++ 离散事件内核；时间、事件、组件引用由原型显式管理，见 [09](./09_discrete_event_kernel.md)。

C43/C46 已确定业务保存切面在统一提交与结果检查之后。下面的文件发布、恢复算法和保存申请协调细节仍为待审方案。

## 2. 保存边界

安全提交边界不是空闲点，也不是 drain：

- 当前 handler 已返回，模型阶段更新完整提交。
- 没有未记录的跨组件副作用或局部超前时间。
- 全部未来影响存在于组件状态或有权威归属的事件记录中。
- C46 在六阶段中的第六阶段处理保存协调；前五阶段的业务提交、完成/超时诊断和结果结算已完成，不能截在一个域已提交、另一个域尚未提交的中间。触发及保存协调细节仍归 Q6。
- 组件激活缓存不能携带唯一业务状态。恢复时按权威事件/状态重建派生索引与激活，不重复安排动作。

保存申请若发生在边界之间，记录“申请时间”和“实际切点”，在下一个合法边界保存，不声称捕获了原申请瞬间。

允许请求在链路中、队列满、服务未完成、响应阻塞或 credit 返回在途。不能为了简化保存偷偷推进到所有事务完成。

C45 禁止追加当前/过去阶段，避免靠同阶段无限重派发来等待安全点。若仍因 handler 不返回或事件规模异常无法到达边界，应明确诊断而非无限等待；宿主 watchdog、预算及错误报告仍需定义。

## 3. 状态清单

| 类别 | 必需信息 | 漏存后果 |
|---|---|---|
| Manifest | 完成标识、schema/模型版本、配置和输入摘要、构建身份 | 文件可读但语义不兼容 |
| 时间 | 逻辑切点、1 ps 网格、阶段约定、两域有理数周期/原相位、边沿序号或等价余数 | 截止时间或采样边沿漂移 |
| 对象 | 稳定 ID、类型、版本和引用关系 | 对象错连或共享关系丢失 |
| 编号分配 | 各身份及排序分配器的下一编号/已分配上界，包括对象已回收时的分配进度 | 恢复后重复分配已使用编号 |
| 事务 | 状态、代际、依赖、终结条件、时间戳 | 丢失责任或重复完成 |
| 资源 | 队列顺序、预留、占用、仲裁位置、credit | 恢复后容量或公平性变化 |
| 动作 | 到达/完成/返回/timeout，排序及有效性 | 丢动作或重复动作 |
| 输入与随机 | 内容身份、游标、发生器内部状态 | 恢复后输入不同 |
| 统计 | 计数、面积、直方图、上次结算点、ROI | 重复累计或跨窗偏差 |
| 输出 | 运行分支和已提交前缀身份 | 恢复后重复拼接输出 |
| 数据内容 | 按已确认 Q1 保存内存与在途读写 payload，记录必要的可见性/提交状态 | 时序相同但读取值错误，或恢复后重复执行写入 |
| 双向传输与 CDC | 当前整消息、发送起止边沿、同步进度/可见时刻、方向及所属接收配额 | 重发、提前接收或重复消耗 credit |
| 仲裁与服务 | 两向 RR、响应分组顺序、下一允许启动边沿、服务到期点、ready-but-uncommitted | 公平性漂移，或把到期但受阻的读写错误执行 |
| Timeout | 原 deadline、固定 G、最终边沿/时刻、宽限状态和计数 | 恢复后重新赠送宽限或误报超时 |

[Q2](./06_memory_transaction_contract.md#8-checkpoint-必须保留什么)确认后，数据状态必须区分“未执行”“已执行待响应”和“源端完成”。保存目标接纳顺序、下一顺序号及冲突关系的权威信息。已执行写不能重做，已固定读响应不能从当前 RAM 重新取值；冷启动清零不得在装载后覆盖恢复内容。

仅比较最终 RAM 不足以发现重复执行同值写；同时比较执行提交身份、次数和响应轨迹。

[Q3](./07_time_clock_cdc_and_timeout.md) 和 [Q4](./08_interconnect_and_memory_service.md)要求额外覆盖：服务到期但响应满时仍占服务槽，读尚未采样、写尚未更新；保存该状态不能通过排空或提前生成结果化简。记录每池 C/F/Q/R 及其消息/返回动作来源，恢复不重新初始化满额 credit。

已预定的链路接续边界也要恢复一致：不能因重建唤醒插入一拍，也不能把切点新返回的 credit 提前使用。C29/C30 已确认本地共享响应池包括正在发送者，必须保存空槽、各源排队顺序与当前发送占用；整条发送结束才释放，不凭恢复过程增加发送暂存容量。

C31–C35 进一步要求保存方向发送序号/下一序号，以恢复同边沿 CDC 批量登记的接纳顺序；记录每源消费宽度 U 的配置身份；恢复原服务到期点及上次实际启动/等价的下一允许启动边沿。II 不是固定周期窗口，失败的启动尝试不改变计数。单次批量登记与消费在统一提交切面内完成，不保存未记账的半个批次。

可重建派生字段必须标明重建规则，并验证与保存的权威状态一致。不能只存 credit 计数而漏存相关 buffer、在途配额和返回动作。

C39 已选择可索引最小堆主动移除：取消/改期不保留旧调度节点等待弹出。快照保存有效动作、必要版本和身份分配位置，恢复时建堆并重建位置索引；不保存旧堆位置作为句柄。C48 不要求永久保留已回收对象的终态历史；额外诊断历史范围仍待确定，不能建立无限历史表。删除调度记录不等于释放关联事务的全部资源。

C40/C41 要求保留有效句柄版本、稳定排序与下一分配状态：Selected 起不可取消/改期，不能通过装载回 Queued 改变边界；真实改期保持 ID 并更新版本/排序，无变化操作不得改变快照状态。

C42 每组件只保留一个尚未派发的最早激活，业务 timer/交付事实仍逐条保存。恢复清单需覆盖待处理事实、最早激活切面/句柄以及后续需求；激活若为派生缓存，须定义唯一重建规则并保持排序，否则显式保存。未来业务动作不能既从组件重建又从事件表再加载一次。

C38 的周期服务需保留原始相位/下一截止点，恢复不能重新给予完整周期。C43 默认周期诊断快照在评估/提交前，而 checkpoint 在统一提交后安全边界；两者是不同用途的切面。保存采样进度/已提交输出前缀，恢复不得再次产生切点已经完成的前态样本。队列时间积分先结算旧区间，恢复后不重复累计。

C44–C46 进一步要求保存/恢复阶段进度：不得重开已完成的空阶段，不得将残留业务 Selected 批次退回 Queued。第六阶段进入时前五阶段应已结算；第六阶段自身保存协调动作的消费/继续位置、同刻多个申请合并方式仍待 Q6 决定。恢复不能因这些尚未冻结的控制细节而重放业务或已完成诊断。

C47/C48 要求区分对象回收与编号回收：只回收前者。即使最近分配的对象全部释放，也必须恢复原编号分配进度，不能取活跃最大 ID 加一。存量动作保留原版本和排序；建堆不分配新模型身份或排序，不重置任何分配器。

保存所有仍有责任或活动使用者的对象及其关系，包括仍被使用的终态记录；已回收对象不因保存过历史 ID 而重新构造。独立的 credit 返回责任可以在父事务已释放后保存/恢复，前提是它不再需要访问该事务，且所需信息完整。拥有引用的目标缺失须拒绝恢复；纯诊断 ID/合法失效弱句柄则不能被当成必须复活的对象引用。C49 已确认三类引用语义，具体 schema 编码待定。

恢复后仍按本对象责任和最后使用者判断回收，不统一等待事务完成，也不直接把宿主引用计数当作完整持久状态。已发布快照中的序列化副本不阻止继续运行时对象回收。相关细化见 [09 的身份与回收规则](./09_discrete_event_kernel.md#47-id-不复用与按责任回收)。

C49 要求恢复保持 OwnerRef/Handle/ID 的原始语义：不能因统一 ID 解析而把弱句柄或标签提升为保活关系，也不能把拥有引用降成弱关系。共享对象只重建一份，对它的拥有关系分别恢复；如使用计数，计数应由权威关系重建或校验，而不是只加载一个数字而遗漏实际使用者。访问/修改权限同样不能因恢复丢失，具体权限保存或由配置重建的方式待定。

C50/C51 已确认成功接纳提交交接与受控 shared_ptr。保存切面只能包含完整交接后的状态或未接纳时的原队列状态，不保存“发送方已放弃、接收方尚未建立拥有关系”的半交接。引用交接不释放仍需占有的响应池槽位；该资源状态必须单独恢复。

每个存活 ID 在新进程创建一个对象及其共享控制块，所有 OwnerRef 连接到该对象；不为每条引用重新创建对象或独立控制块。不保存地址、控制块内容或 use_count()，由恢复出的拥有关系自然建立宿主计数。临时装载强根在正式关系及校验完成后解除，Handle/ID 不变成永久强根。完整序列化方案仍待 Q7，不能因选用 shared_ptr 就视为自动支持 checkpoint。

C52 要求保存超时检查到原事务的拥有关系和事务到检查的弱句柄。已完成且不再位于 outstanding 的事务，如果仍由未取消检查持有，也必须保存；恢复后的检查读同一事务终态，不新建第二份完成状态对象，不重复完成计数，不重置原 deadline。检查取消/结束后的引用释放遵守 C48。

C54/C58 要求有效配置与本地文件位置分离：保留配置值及兼容性所需身份，不把开发者 checkout 的绝对路径当作恢复依赖。涉及外部文件的相对引用须明确基准与内容身份，具体映射随配置入口/快照格式冻结。暂缓 CLI/JSON 选择不允许省略配置校验，也不预先选择快照文件格式。

## 4. 保存流程与文件发布

候选流程：

```text
接受保存申请
 -> 到达合法提交边界
 -> 暂停模型派发，不推进模拟时间
 -> 检查组件能力和资源不变量
 -> 结算切点处统计并构造一致快照
 -> 写临时目标、校验内容
 -> 发布完整 checkpoint
 -> 继续原运行或按用户要求退出
```

建议首版同步完整快照；不引入需要写时复制的并发后台保存。

文件格式尚未决定。无论最终使用单文件还是目录包，都要求：

- 未完成写入不能被当成有效快照。
- 清楚区分版本/配置兼容校验和文件完整性校验。
- 发布过程有失败语义，不能覆盖唯一可用快照后才发现写入失败。
- 进程中断测试与机器掉电耐久性是不同保证。原子重命名不单独保证掉电后数据持久，是否要求 `fsync`/目录持久化应按平台另行定义。
- 保存失败必须显式报告；是否继续原运行由策略确定，不能生成成功标记。

首版建议同环境严格恢复。校验和不提供来源认证；加载器仍需检查长度、计数、容量、引用、时间范围和未知类型，避免把损坏内容当合法模型。

## 5. 新进程恢复

候选顺序：

1. 验证完成标识、格式、兼容身份、输入和配置。
2. 创建固定组件结构和稳定 ID 注册表，不安排业务事件。
3. 载入对象自身状态，不依赖其他对象已完成装载。
4. 解析引用、共享 payload 和事务关联。
5. 恢复事件、随机状态、输入游标和观测状态。
6. 检查守恒、容量、合法阶段和所有截止时间。
7. 直接设置内核当前逻辑时间为保存切点，恢复时钟累计状态并重建事件日历/派生索引，不重复注册业务事件。
8. 从指定逻辑阶段继续执行。

失败时不进入半恢复运行。

### 直接恢复逻辑时间

C36 移除原 SystemC 相对时间加恢复基点的方案，内核直接维护一个权威逻辑时间：

```text
logical_now = checkpoint.logical_cut
event.due_time = saved_absolute_due_time
```

原运行的切点是 100 ns，动作截止 140 ns，则恢复后仍从逻辑时间 100 ns 继续；若没有更早动作，内核直接推进至 140 ns。剩余模拟间隔为 40 ns，不需要宿主等待，也不从零重新模拟。

反复保存恢复时，新切点仍使用统一的逻辑时间；不能重新编号时间或追加历史偏移。局部边沿按原相位和累计有理数周期计算，不能在恢复时重置余数或重新启动零相位时钟。服务、CDC 和 timeout 都继续等待原到期点，不能重跑完整延迟或重新赠送宽限期。

到期时间等于切点的动作如何处理，必须依赖保存阶段契约决定，不能靠“时间不早于当前”一条检查放行。

## 6. 兼容性与扩展

首版建议锁定模型版本、schema、语义配置、输入与运行环境。文件能解析不代表可以恢复。

以下需独立设计，不能作为普通恢复：

- 修改 buffer 容量、路由、时钟、地址映射。
- 改换精度模型，或从 detailed 切换到近似模型。
- 将旧 schema 自动补字段后继续执行。
- 多宿主线程/分区之间迁移。

未来实验分支可以允许经过验证的参数修改，但应声明是否需要排空、状态映射和重新预热，不承诺与原运行逐事件一致。

Checkpoint 和 record/replay 也不同：首版建议受控离线输入；将来接实时外部输入时需记录值和注入位置。不可回滚的真实外部副作用不能靠恢复内部状态撤销。
