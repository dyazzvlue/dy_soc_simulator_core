## 1. 决策与不变的语义

**已确认 C36：**纯 C++ 离散事件内核成为首版唯一时间推进与调度基础，替代 C3 的 C++ + SystemC 路线。组件继续遵循已确认的显式状态、可序列化动作契约，不把暂停线程或协程帧作为可恢复状态载体。

保留原模型契约：

- 1 ps 逻辑网格、有理数时钟、源/互连域与内存域。
- 边沿前状态决策、统一提交、CDC 与 no-bypass。
- 请求/响应独立带宽、消息 RR、有限 credit、整消息传输。
- 冲突启动门控、真实 payload、共享响应池、发送结束释放。
- 固定 timeout 宽限、新进程恢复后模型可观察轨迹一致。

SystemC 进程调度被移除，不意味着模型时钟、并发资源或跨域行为消失。模拟时间也不是宿主 wall time。

首版不实现通用信号网络、任意线程 `wait`、HDL delta-cycle 兼容或通用协程框架。将来如需 SystemC 适配，应单独定义同步和恢复边界，不在首版承诺双后端。

补充已确认：

- C37：模型由单宿主线程执行；以后依据性能证据再决定是否引入多线程同步，不在首版实现并行调度。
- C38：统一周期服务仅用于采样、维护或明确的周期行为；业务动作保持精确时刻，不等待公共同步点，也不允许组件局部超前后再交换结果。
- C39：全局事件日历采用可索引最小堆；取消/改期主动移除旧队列记录，不采用惰性失效记录堆积方案。
- C40：只有 Queued 动作可取消/改期，Selected 起锁定；事务最终超时仍诊断并终止运行，不新增取消事务后继续执行的协议。
- C41：实际改期保持 EventId、更新版本与入队排序序号；时间/阶段均未变化的合法改期是无操作。
- C42：每组件只保留一个尚未派发的最早下一次激活，业务事实独立保存；当前 Selected 期间的新需求转入后续待激活状态。
- C43：默认周期诊断快照读取本时刻模型评估/提交前状态；完成/超时结算与 checkpoint 保持提交后，队列占用采用时间积分。
- C44：每个时刻的每个阶段开始前，一次性将该阶段全部待执行事件转为 Selected；后续尚未进入阶段的事件仍是 Queued。
- C45：阶段开始后禁止新增或改期到该时刻当前/已结束阶段；合法后续阶段或未来时刻可以安排，不静默加 1 ps，不产生同阶段追加批次。
- C46：六阶段顺序为前态观察、到期收集、候选评估、仲裁与提交、结果检查、保存边界；全部时钟域共享，仲裁与提交内部先完整裁决再提交。
- C47：稳定 ID 不回收再分配；对象内存可以释放或复用，恢复仍保持编号分配进度。
- C48：各对象自己的责任终结且最后一个活动使用者结束后回收，不统一等待整笔事务结束；回收不撤销仍欠的业务或资源责任。
- C49：持久引用区分拥有引用 OwnerRef、弱句柄 Handle、身份标签 ID；只有拥有引用延长寿命，弱句柄访问前校验，ID 仅用于关联，修改权限与保活责任分开。
- C50：接收方成功接纳提交时交接责任；入队后允许必要使用者共享保活，交接失败仍由原队列持有，不提前释放。
- C51：首版 OwnerRef 底层采用 std::shared_ptr，通过受控接口管理；Handle 保留稳定 ID/适用版本，checkpoint 保存对象与关系而非智能指针内部状态。
- C52：超时检查持有原事务的 OwnerRef，事务反向保存弱句柄；不为首版另建独立完成状态对象。
- C53：按七条原则和四组最小规范收敛，不改变外部语义的内部细节在实施中自主决定；本轮不授权编码。

## 2. 最小内核职责

```text
配置 / 工作负载 / 实验控制
              |
Source / Link / CDC / Credit / Memory
              |
显式状态 + 资源账本 + 统一提交协议
              |
确定性离散事件内核
  逻辑时间 | 时钟计算 | 事件日历 | 身份与有效性
              |
Checkpoint / Trace / 统计 / 不变量
```

建议职责如下，不要求每项都成为一个类：

| 职责 | 管理内容 | 不负责 |
|---|---|---|
| 时间服务 | 当前逻辑时间、有理数边沿、周期到绝对时间转换 | 宿主定时器或真实时间节拍 |
| 事件日历 | 有效动作的到期点、阶段、确定性派发 | 用排序键代替 RR/资源仲裁 |
| 组件注册表 | 稳定组件身份与动作类型分派 | 序列化虚函数表或函数地址 |
| 身份管理 | 事件/事务身份与失效范围 | 以指针值作为长期身份 |
| 提交协调 | 同刻候选评估、资源检查、统一更新 | 因组件遍历顺序给予同拍旁路 |
| 快照协调 | 合法边界、完整状态清单、校验与装载 | 任意机器指令处冻结 |

首版已确认单宿主执行线程、全局事件日历及可索引最小堆。单线程不限制模型内的双向传输、并发服务和多时钟域；它只规定宿主执行方式。并行、多级队列或时间轮不能仅以“应该更快”作为引入理由。

## 3. 组件不再是挂起的进程

组件接受一个明确动作，完成本次处理后返回。跨时间等待体现在状态和到期动作中，而不是宿主调用栈中。

以服务目标为例：

```text
Waiting
 -> Serving（持有服务槽，记录到期边沿）
 -> ReadyUncommitted（到期但响应池满，仍未操作 RAM）
 -> Committed（执行读写，形成有槽位的响应）
 -> 响应继续排队/传输，直到源端完成
```

服务计时到期只使计时条件成立；是否提交仍取决于已确认资源规则。响应阻塞期间，不需要每个事务持有一个等待线程。

组件契约应区分：

1. 配置和结构：类型、参数、连接、时钟域。
2. 权威状态：队列、payload、计数、依赖、所欠资源责任。
3. 未来动作：由事件表保存，或按唯一规则重建，不能两者重复安排。
4. 派生缓存：可重建索引和宿主内存布局，不决定未来行为。
5. 行为实现：按动作类型调用的 C++ 逻辑，不进入快照。

具体构造/装载/校验/启动 API 尚未冻结。构造和加载仍不得提前注入业务。

## 4. 事件与句柄

### 4.1 三类概念

- Handler 是处理逻辑，不是持久身份。
- Event handle 指向某次可调度动作，不等于事务本身。
- Transaction ID 标识端到端责任；一笔事务可能拥有多个先后事件。

把进程句柄换成普通指针，并不能获得可恢复性。推荐使用可校验的逻辑身份；运行时允许有派生指针缓存，但快照中保存稳定 ID。

### 4.2 候选事件记录

| 字段 | 目的 |
|---|---|
| 绝对到期 tick、逻辑阶段 | 何时处理，是否合法 |
| 稳定排序序号 | 同阶段确定性与恢复一致性 |
| 事件身份、有效版本 | 取消/重调度后识别旧动作 |
| 目标组件 ID、动作种类 | 定位接受者与对应行为 |
| 必要事务 ID、参数或 payload ID | 重建该动作需要的上下文 |

这些是逻辑字段，不是已冻结的 C++ 类型、位宽或磁盘结构。禁止直接保存 `std::function`、lambda 捕获、函数地址、虚表或迭代器。

建议排序键为 `(到期时间, 阶段, 稳定序号)`，但同刻处理必须遵守第 5 节的集体提交规则；仅逐个出堆并直接修改可见状态仍会违反 no-bypass。

### 4.3 两种取消方案与已选路线

| 方案 | 操作方式 | 优点 | 代价 |
|---|---|---|---|
| 惰性移除（未采用） | 旧版本标失效，弹出时跳过；改期另插新记录 | 普通堆即可，逻辑标记简单 | 失效节点占内存、额外弹出/清理；可能延迟释放 payload |
| 可索引堆主动移除（已确认 C39） | 通过身份查到堆位置，取消删除；改期移除旧调度记录并发布新记录 | 无失效调度节点长期堆积，队列接近有效动作集合 | 每次交换/删除都必须维护位置索引，失败路径与恢复检查更复杂 |

两者可以提供相同业务语义，主要差别在调度实现。用户明确选择第二种，不以“实现简单”为由改回惰性取消。历史结果诊断表与堆中失效节点是不同概念；C48 不要求永久保留已回收对象的历史，额外诊断历史如需保留须单独限定范围。

### 4.4 可索引堆的候选结构与不变量

```text
逻辑句柄（事件 ID、有效版本）
               |
事件控制记录 --+--> heap_position
                         |
                  heap[position] --> 对应事件记录
```

事件身份不是堆下标。上浮、下沉或删除导致位置改变时，同步更新反向索引；不向组件暴露堆迭代器或数组地址。

必要不变量：

1. 每个处于 Queued 状态的有效动作，在堆中恰好一份。
2. 堆节点与位置索引双向一致，根节点满足已定义的最小排序键。
3. 已取消、已执行、已转入当前时刻待处理批次的动作，不保留有效堆位置。
4. 版本、ID 与排序序号不因堆交换改变。
5. 已执行业务的副作用不能通过删除调度记录撤销。

若身份查询使用哈希表，查找通常为平均 O(1)，删除/改期的堆调整为 O(log N)；这不是对哈希最坏情况或整体内存分配耗时的保证。容器和身份编码尚未冻结。

### 4.5 操作与句柄语义

**已确认 C41：**Queued 动作真正改变到期时间或阶段时保持 EventId，增加版本、分配新的入队排序序号并返回新句柄。例如：

```text
原：E42 / version 7 / due 100 ns
改：移除旧队列记录 -> E42 / version 8 / due 80 ns / 新排序序号
结果：堆中只有新版本；旧 version 7 句柄不得修改 version 8
```

主动移除并不替代版本校验：组件仍可能保存旧句柄。C47 已确定 EventId 不复用，但同一事件改期后仍需区分旧安排与新安排；这是 version 的职责。底层内存槽复用策略和字段宽度尚未冻结，不能把槽下标当成 EventId。

建议操作流程：

- 安排：检查时间/阶段、目标与参数，分配身份和稳定顺序，登记并插堆。
- 取消：检查句柄及动作状态，删除堆节点并维护索引，再按该动作的所有权释放引用。
- 改期：先验证新时刻、阶段和必要容量，再完整替换旧调度记录并发布新版本。不能改期失败后把原有效动作也丢掉；若系统无法维持原状态，应明确终止而非继续半更新。
- 派发：从堆移除并转入明确的处理状态，不能仍伪装成 Queued。

实际改期的新排序序号表明这是一份新的调度安排；相同到期时间和阶段下，不因 EventId 创建较早就插到既有安排之前。排序序号只控制调度稳定性，不替代消息 RR 或资源仲裁。

若时间和阶段均未变化，则为无操作，保持版本、排序序号及原句柄，不删除再插堆。仍需先校验句柄有效且动作处于 Queued；旧版本或 Selected 动作不能利用“无变化”绕过生命周期检查。

本改期接口只改变调度时间/阶段，不隐含修改动作类型、目标或 payload。其他字段变更是否需要独立操作仍属 API 设计余项。

建议区分取消成功、旧版本、不可取消状态与不存在的句柄，返回明确状态并按调用契约诊断。控制记录已按 C48 回收后，可明确报告不可解析/无效句柄，不保证仍能区分“过去已取消”与“过去已完成”；具体错误枚举尚未冻结，不建立无限 tombstone 表。

### 4.6 已出堆事件与取消边界

**已确认 C40：**生命周期语义为 `Queued -> Selected -> Executing -> Completed`；取消仅允许从 Queued 转入 Cancelled，改期也只允许 Queued。

Selected 表示动作已出堆、被选入当前处理批次，即使处理函数尚未被调用也不可取消或改期。执行中的动作不通过取消回滚，终态不被重新激活；具体枚举名不作为已冻结的 C++ API。

**已确认 C44：**按 `(逻辑时刻, 阶段)` 选入批次。阶段开始前一次性将这一对键下全部有效待执行事件从堆移入 Selected 集合，再开始任何处理。不是执行到哪个事件才锁定哪个。

因此同阶段事件不能互相取消，即使被取消者的 handler 尚未调用；后续尚未进入阶段的事件仍为 Queued，符合句柄/所有权等契约时可取消或改期。取消后续动作不等于任意组件可以撤销他人的业务责任。不能把“查不到堆位置”一律报告为不存在。

同阶段派发仍按稳定顺序处理；整批锁定解决取消边界，不自动解决资源仲裁公平性。资源裁决仍按已有 RR、接纳顺序等模型规则。

取消事件不自动完成事务、归还 credit 或回滚写。即使该事件拥有一个 payload 引用，释放该引用也不等于删除其他队列/事务仍持有的数据责任。

“超时取消”经用户澄清后不作为新增机制：仍执行 C20，最终 deadline 先处理正常完成，未完成才诊断并终止，不撤销已提交操作、不返还资源后继续其他业务。

依 C46，源完成在“仲裁与提交”落实，最终超时检查在后续“结果检查”才 Selected。若检查未被提前取消，它执行时读取已结算的完成状态并判为成功；Selected 后不再尝试撤销检查。这是检查动作的正常语义，不是偷偷绕过 Selected 锁定。具体 timer 清理 API 仍待设计，正确性不能依赖清理是否执行。

模拟 deadline 不能抢占卡住不返回的单线程 handler；宿主 watchdog 是另一类诊断，不在本次规则中新增实现。

### 4.7 ID 不复用与按责任回收

**已确认 C47/C48：**编号不复用，记录不永久保留。事件、事务、payload 等对象的控制记录及所需身份/版本/排序信息保留至本对象责任完成、最后一个活动使用者结束，再在不破坏当前处理的安全点回收。

```text
对象责任已终结
且不存在未来动作还需访问该对象
且不存在队列、处理批次或其他拥有者仍需使用该对象
    -> 可释放记录和本对象拥有的引用
    -> 已分配 ID 不放回可用编号池
```

“最终提交”在这里指本对象最终责任完成，不是统一指 RAM 执行提交、第四阶段结束或整个仿真结束。具体回收点可以随对象而异，不强制统一第六阶段回收。C51 已选择 shared_ptr 管理 OwnerRef 的宿主寿命，但业务责任仍须显式管理；分配器/对象池及精确回收 API 尚未冻结。

| 对象 | 最后使用者与释放边界 |
|---|---|
| 业务事件控制记录 | 取消或完成后，确认堆/Selected 批次/handler/必要控制使用者均已脱离；不能一出堆就销毁 |
| 事务记录 | 本事务完成与其他必要检查/依赖使用者都结束；写入 RAM 并不代表 ACK 责任已完成 |
| 响应 payload | 传输、CDC、接收消费及其他拥有者不再使用后释放；本地发送槽释放不自动销毁仍在 CDC 中的数据 |
| Credit 返回记录 | 额度正确归还、相关检查与使用者结束后释放；源事务结束不代替 credit 返回 |
| 组件记录 | 静态组件通常存活到模型结束；动态移除并非首版已批准能力，不能在仍有目标事件时删除 |

责任可以显式转移。例如独立 credit 返回记录已经携带必要池身份与数量，不再需要访问已完成事务时，无需强留整笔事务；但不能丢掉返回记录或把未来所需信息也一并释放。

引用计数归零本身不是业务正确性证明。若仍欠响应/credit 而没有拥有者，应诊断所有权遗漏；也不能用循环强引用让对象永远不可回收。具体所有权表示在后续 API 设计冻结。

### 4.8 编号、版本、排序与内存位置的区别

- **稳定 ID：**同一运行及其 checkpoint 续跑中，每个身份命名空间内不重复发给新对象。跨类型共享一个分配器还是使用类型化命名空间，尚未冻结。
- **事件 version：**属于某一个 EventId，实际改期增加，无变化改期不变；不同 EventId 可以各有相同的版本数值。事件结束后 version 不必作为全局历史永久存储。
- **入队排序序号：**表示一次有效调度安排；新建或实际改期产生新序号，存量事件恢复保留原序号。已消耗序号不能因对象释放或堆重建而重新分配给另一安排。
- **宿主内存位置：**允许复用，但新对象必须使用新 ID，旧句柄不能因为地址或槽位置复用而命中新对象。

保留必要信息不等于保存所有旧版本的完整快照。当前事件记录保留当前版本/排序；仍有使用者持有的旧句柄保留其值用于校验。需要实际访问对象的拥有者会延长寿命；纯 ID 诊断标签或弱句柄不应永久阻止回收，后续解析失败须明确报告。C49 已确认引用语义分类，具体接口仍待设计。

每类编号分配器的下一编号或已分配上界须作为持续状态保存，即使所有对应对象都已释放。C57 选择 std::uint32_t/std::uint64_t 等固定宽度无符号整数作为 ID 等字段的类型方向；每个字段使用哪一宽度、保留值及合法范围仍需明确，不把用户的 uint_32 表述当成标准类型名。建议单调递增分配；耗尽时明确失败，禁止回绕、重置或通过重编号静默继续。

例：已分配至 E100，但 E90–E100 都已释放，当前活跃最大 ID 为 E89。恢复后仍应从 E101 或已记录的下一合法编号继续，不能由活跃最大值推导出 E90。版本和排序计数同样必须检查溢出。

从同一快照做多个独立实验分支，会重放相同逻辑身份序列；这是不同运行分支，不是同一续跑内的 ID 复用。输出建议另带运行分支身份，不改变模型内部 ID 来破坏 A/B/C 轨迹对照；分支标识格式归 Q8。

已写入的日志和已完成快照拥有自己的序列化数据，不应反向延长宿主对象寿命。尚未完成复制的输出缓冲若仍访问对象，则属于活动使用者，须纳入所有权。

### 4.9 拥有引用、弱句柄与身份标签

**已确认 C49：**以下是三类持久引用的语义名称，不是已冻结的 C++ 类型或磁盘编码；C51 进一步选择 shared_ptr 作为 OwnerRef 的底层实现，见第 4.10 节。

| 类别 | 保活效果 | 访问约束 | 典型用途 |
|---|---|---|---|
| OwnerRef：拥有引用 | 持有期间阻止目标回收 | 保活不授予任意写权限；仍遵守调用者权限和阶段规则 | 队列持有消息、CDC 持有 payload、动作持有所需上下文 |
| Handle：弱句柄 | 不延长寿命 | 访问前解析并校验目标、适用的版本、操作权限与状态；失效明确返回，不指向其他对象 | 请求取消/改期、查询事件状态 |
| ID：身份标签 | 不延长寿命 | 仅关联身份，不直接提供访问或修改能力 | 日志、trace、统计关联、诊断上下文 |

ID 值可以是引用内部的身份字段，但持有一个编号不等于持有拥有引用，也不等于获准访问对象。版本规则依对象类型定义；EventId 的改期 version 不能机械应用到所有事务或 payload。

在持久引用中只有 OwnerRef 承担保活；这不取消 C48 的另一条件，即对象自身责任必须已终结才能回收。Handle 解析成功也不自动赋予长期拥有权或修改权，不能通过解析绕过 Selected 锁定、阶段限制或动作控制权限。

取消/改期接口至少需要覆盖目标存在性、事件版本、调用者控制权限、Queued 状态及时间/阶段合法性。验证次序、权限编码和错误枚举仍待确认，不应向任意持有 ID 的组件暴露无约束的可写对象。

**临时借用的候选约束：**handler 内可以短期借用已保活对象，期间必须保证对象不被回收。借用不序列化，不允许把裸指针藏入未来动作；后续动作确需访问时必须有明确的保活责任。这是运行时访问方式，具体借用 API/有效范围仍待冻结，不是第四类持久引用。

**对象存储的建议：**由对象存储/注册表管理记录和解析身份，但登记本身不是无限期保活理由。生命周期由业务责任与真实使用关系决定，不能让注册表成为所有对象的永久自引用。C51 已选择 shared_ptr 保活，注册表容器、弱索引或受控强引用移除策略、对象池仍待设计。

**已确认 C50：**在接收方成功接纳提交时交接；入队后允许有必要的并存使用者共享保活，失败时仍由原队列持有。不先释放再发现无处交付，不因候选评估通过就转移。交接过程不能改变已确认的队列容量、credit 或 no-bypass 规则；临时两个保活引用不等于两份硬件消息。

```text
响应队列 -> 发送状态 -> 传播/CDC 状态 -> 源接收队列 -> 消费结束
             各阶段明确承担 payload 保活责任
```

**已确认 C52：**超时检查通过 OwnerRef 持有原事务，事务侧保存取消检查所需的弱句柄，避免双方强拥有形成环；首版不另建独立完成状态记录。

事务从源 outstanding 移除不代表立即销毁。若最终检查未提前取消，检查仍可读取原事务的已提交终态，并按既有完成优先规则结束；不能重复累计完成。检查合法取消或执行结束后，在不再需要访问该事务的安全点解除这份拥有责任，是否销毁仍由 C48 的全部条件决定。Selected 后不可取消，超时失败仍诊断并终止，不新增事务回滚。

该选择可能使已经完成的事务因未清理的检查而保留到截止时刻，是明确的内存代价；正确性不依赖提前取消优化。应测量检查持有的终态对象数量和内存，不能通过丢弃必需引用或只看 use_count 消除这项开销。

必需状态缺失不能被解释为“事务大概已完成”而默认成功。可失效的弱通知如确有业务需要，须单独定义其合法失效语义，不能作为全部动作的成功回退。

Checkpoint 必须区分三类关系：拥有目标缺失是错误；合法失效弱句柄可以保留其值但不能访问成功；身份标签不要求对应运行时对象仍存在。恢复不得把 Handle/ID 隐式提升为 OwnerRef，也不能把原 OwnerRef 降成不保活关系。具体持久表示、共享计数的重建或核对方法仍归 Q7。

### 4.10 受控 shared_ptr 与接纳交接

**已确认 C50/C51：**首版不自建引用计数系统；OwnerRef 以 std::shared_ptr 为宿主保活基础，业务状态、硬件容量及稳定身份仍独立建模。受控接口的具体名称、包装类型与是否使用对象池尚未冻结。

| 交接状态 | 拥有关系与业务效果 |
|---|---|
| 评估候选 | 原队列保有责任，不能仅凭可接收判断就出队或转移 |
| 成功接纳提交 | 接收状态先取得必要拥有关系，完成责任交接；原队列解除已经结束的拥有关系 |
| 正常背压/拒绝接纳 | 原队列保留消息、拥有引用和原有顺序；返回明确阻塞/拒绝结果，不留下已提交的接收状态 |
| 不变量破坏或无法维持完整交接 | 明确报错，不伪装接纳成功，也不遗失原消息后继续运行 |

失败交接不能额外扣 credit、重复占槽或推进成功计数；如有候选预留，须在未提交范围内解除。正常背压不是模型故障，具体结果枚举和异常处理接口仍待确认。

“入队后允许共享”是使用者资格规则，不强制在入队时转换指针类型。建议创建时就使用 shared_ptr，入队前只有创建方拥有，入队后通过接口建立必要共享。复制强引用不授权新业务消费、写入或资源占用；共享使用者范围及只读视图接口继续细化。

引用交接与硬件资源释放点分离。响应发送启动时可以让发送状态接管 payload，但本地响应池的正在发送占用必须持续至发送结束；之后传播/CDC 仍须保活数据。原队列若仍承担必要读取责任，可以继续持有引用；否则保留必要的资源占用状态，不为此强留无用 payload 引用。所有做法均须保持 C30 和接收池 C/F/Q/R 账本。

shared_ptr 的使用边界：

- 不使用 use_count() 决定业务完成、队列出入、credit 返回或是否有权修改；临时副本会改变计数，计数不描述未履行责任。
- 活动业务责任必须有明确保活者。先完成或合法转移责任，再释放对应强引用；不能期待 shared_ptr 自动识别仍欠响应/credit 的业务错误。
- 禁止从同一受管理裸地址重新创建独立共享控制块；共享者必须复用已有拥有关系，避免双重销毁。
- 不允许强引用环造成永久保活。回指使用 Handle/其他非拥有关系；注册表不得成为未清理的永久强根。具体关系图继续按对象类型设计。
- 未来动作需要的持久拥有引用须位于可枚举的组件/动作状态中，不藏入不可序列化闭包；临时本地副本不作为 checkpoint 关系。
- Handle 以稳定 ID/适用版本为权威。可选 weak_ptr 仅是运行时缓存，不跨进程保存；lock 成功仍须检查版本、状态、权限，不能代替生命周期校验。
- 共享保活不授予共享写权限。首版单宿主线程也必须遵守阶段和修改职责；shared_ptr 不使被指向对象自动线程安全。

恢复时每个存活稳定 ID 创建一个受管理对象及其共享控制块，然后连接权威拥有关系；弱句柄和身份标签不增加持久强引用。加载过程可以有临时强根，校验和正式拥有关系建立完成后必须解除，不能让恢复后的对象比连续运行永久多一个拥有者。保存的是字段、ID 和关系，不是地址、控制块内存或 use_count 数值。

shared_ptr 的复制/销毁和分配有宿主成本，常见实现包含引用计数同步；目前没有实测证明其为瓶颈。首版先保证正确性，减少无意义复制；后续只有测得瓶颈才评估替换 OwnerRef 内部实现，不凭“单线程”直接宣称零开销。

## 5. 时间推进与同刻提交

没有操作系统定时器，也不需要为每个时钟建一个宿主线程。有理数时钟保留原相位及精确累计状态，使用 [07](./07_time_clock_cdc_and_timeout.md) 的边沿公式。

**已确认 C46：**同一时刻 t 按固定六阶段推进。下列编号只说明顺序，不冻结 C++ 枚举名或序列化编码：

```text
找到下一有效动作时刻 t
 -> 1 前态观察：结算上一段积分，按需只读采样
 -> 2 到期收集：登记本时刻到期事实
 -> 3 候选评估：基于同一边沿前状态及允许的到期条件提出候选
 -> 4 仲裁与提交：先完整裁决/预留，再统一提交
 -> 5 结果检查：读取已提交完成状态，检查最终 timeout、结算结果
 -> 6 保存边界：协调合法 checkpoint 申请
```

每个阶段入口先完成 C44 的整批选取，再处理该阶段工作。全部时钟域共享此顺序，不允许源域先完成六阶段、内存域随后再完成六阶段。模型前态在本时刻业务更新前保持一致；积分和只读观测不能改变业务可见状态。

到期收集只形成事实，例如服务计时满足、消息将可见、credit 将登记；不能提前修改候选评估所见资源。新消息/credit 直到提交才登记，供下一合法本域边沿决策。已预定服务/链路结束按原规则可参与本拍资格。

**已确认 C45：**当前阶段一旦开始，不允许新增或改期到该时刻当前阶段或已经结束的阶段。允许安排尚未开始的后续阶段或未来时刻，但仍须通过动作职责、时钟、CDC 和 no-bypass 检查。非法安排明确报错，不偷偷加 1 ps，也不自动生成同阶段的下一批。

同阶段内部普通函数调用不等于调度新事件，但不能用递归跨组件调用绕过阶段和状态契约。比如仲裁与提交内部使用已收集候选先完整裁决，再应用更新；不能由仲裁回调新建“当前阶段提交事件”来继续本阶段。

若业务动作到期但还未到组件处理边沿，需要显式保留待处理状态，不因“事件已弹出”就丢失。真正需要零时间组合迭代的模型不在首版阶段机制中获得自动支持。

跳过空闲边沿必须有依据：组件没有可运行工作，且没有遗漏周期副作用；背压解除、II 到期、deadline、统计窗口等必须能在正确时刻重新激活相关组件。不能用“当前事件堆空”直接证明运行成功。

### 5.1 组件的主动与被动激活

用户提出组件具有事件/定时唤醒及关联组件触发能力，C42 已确认最早下一次激活策略，C46 已确认六阶段顺序。以下为其分层；具体 API、激活重建与枚举编码仍需细化：

```text
组件状态 / 输入队列 / 多个业务 timer
                 |
主动到期条件或被动状态变化
                 |
请求在合法边沿/阶段评估组件
                 |
去重后的组件激活 -> 评估候选 -> 统一提交
```

**主动触发**：源的下一次注入、服务计时到期、链路发送结束、II 最早发起边沿、周期维护。

**被动触发**：完整消息可见、credit 可见、响应槽释放、冲突前驱提交。发起者登记事实/交付记录，不直接递归调用对端业务逻辑绕过时钟和提交阶段。

跨域交付遵循 CDC；域内状态变化同样遵循 no-bypass。关联关系是输入/输出和资源依赖，不要求组件共享时钟，也不等同宿主线程同步。

### 5.2 多业务事件与一次评估

一个组件可以同时拥有多个服务到期、消息交付和统计动作；不能只保存一个通用 event 然后覆盖其他动作。

**已确认 C42：**每组件只保留一个尚未派发的最早下一次激活；“最近”指按合法逻辑时间/阶段最早发生，不是最后收到的请求覆盖旧请求。业务 timer、交付与资源变化记录逐条保留，激活只是评估需求的调度摘要。

相比按 `(组件 ID, 评估边沿, 阶段)` 保存多个未来激活，它减少日历中的激活记录，但增加重新计算和不漏唤醒的责任：

| 情况 | 已确认行为及必要推导 |
|---|---|
| 新需求比 Queued 激活早 | 先保存业务事实，再将该激活提前到合法切面，遵守 C41 改期规则 |
| 新需求与 Queued 激活同切面 | 合并评估需求，保留全部事实，不重复派发 |
| 新需求比 Queued 激活晚 | 业务事实仍保存；不将最早激活推迟，不为每个未来原因都新增激活 |
| 当前激活已 Selected/Executing | 不修改当前事件；新需求记录为后续待激活状态，不能被当前评估结束时清空 |
| 本次评估结束 | 从尚未处理事实/等待条件重新计算下一合法激活；没有需求才休眠 |

例如业务需求在 100/150 ns，堆中只留 100 ns 的激活；新增 80 ns 需求后提前至 80 ns。执行 80 ns 评估并只处理该切面有资格的事实，再计算 100 ns，之后计算 150 ns。未来事实并未被删掉。

“一个尚未派发激活”不禁止当前已有 Selected 激活和后续需求同时存在；何时将后续摘要物化为 Queued 记录须由阶段 API 定义，但任何时刻不得产生两个尚未派发的激活。

同边沿不同阶段仍须依次处理，不能压成一次无阶段调用。C45 禁止重新打开当前/过去阶段：在“到期收集”可以根据服务到期安排后续“候选评估”；在“仲裁与提交”产生的资源可用通知，则要求模型明确选择下一合法本域边沿的评估，不得请求已经过去的本拍评估后让内核自动修正时间。

最早激活不是豁免阶段检查的通道。当前评估批次 Selected 后，不能靠修改其待处理原因让后执行的组件看见先执行组件的新状态。当前评估只使用既定可见事实；新产生的跨组件需求保留到合法后续切面。若模型本意要求重新评估当前阶段，应明确报非法调度，不静默丢弃或滚到下一拍。

例：边沿 20 同时服务到期、新请求入队和响应槽释放。组件可以一次评估，但：

- 已预定服务到期可参与本拍资格判断。
- 新请求本拍不能启动。
- 新释放响应槽本拍不能用于提交。
- 新可用资源必须触发下一合法边沿的评估，不能因本拍已激活就吞掉下一拍激活。

因此激活表示“需要检查”，不是“现在可以无条件处理全部队列”。

### 5.3 周期服务不是业务屏障

C38 已确认：统一周期用于采样、维护或明确的周期行为，不允许精确业务事件等待该周期。A 在 103 ns 到期、B 在 107 ns 到期，均按原时刻处理；周期服务在 110 ns 运行不改变它们。

不相关组件共享的是一个权威逻辑时间，而不是允许各自超前的局部时间。首版不实现多线程 barrier、时间解耦或分区回滚。

周期任务需保存原点、周期/边沿计数、下一截止点和阶段；恢复不从切点重新开始一个完整周期。

**已确认 C43：**默认周期诊断快照读取本时刻模型统一评估/提交前状态，不是“某组件已经改过、另一组件尚未改”的混合状态。采样只观察，不推进业务、返还资源或改变仲裁。

| 用途 | 观察/结算边界 |
|---|---|
| 模型决策 | 提交前状态，继续遵循既有契约 |
| 默认周期诊断快照 | 本时刻模型评估/提交前，用于解释本拍决策 |
| 完成计数与超时结果 | 提交与完成优先裁决后结算 |
| Checkpoint | 统一提交后的安全边界；具体触发与失败策略归 Q6 |
| 队列平均占用 | 时间积分，不靠周期采样近似 |

例：边沿 20 前响应池满，本拍有响应发送结束。提交前快照显示满，可以解释本拍为什么不能用刚释放槽提交另一笔事务；提交后空槽用于下一时间区间。

时间积分在 t 先用旧占用结算 `[last_time,t)`，再以提交后占用开始下一段，不能因同刻发生多个动作重复累计面积。周期快照看前态不改变这条积分规则。

周期维护若改变模型状态，应走它自己的已定义阶段，不得混入只读采样回调；具体维护动作与阶段仍需另定。

周期任务不能永久阻止正常结束；输入停止、业务责任排空与周期任务停用的关系在 Q5 定义。不能因为周期事件仍存在就永不退出，也不能因为它们存在就掩盖业务已无推进路径。

### 5.4 安排/改期合法性与空阶段

| 当前执行位置 | 新动作目标 | 结论 |
|---|---|---|
| t 的阶段 p 已开始 | 时间小于 t | 拒绝，时间倒退 |
| t 的阶段 p 已开始 | t，阶段小于或等于 p | 拒绝，过去或当前阶段不可追加 |
| t 的阶段 p 已开始 | t，尚未开始的阶段 q > p | 可安排，但须满足动作职责/可见性/时钟规则 |
| t 的阶段 p 已开始 | 时间大于 t | 可安排，但须通过正常输入与时钟检查 |

Queued 动作改期同时遵守上述表和 C41；Selected 起不可改期。当前阶段所有事件已整批 Selected，因此当前阶段也不存在可借 no-op 改期规则绕过锁定的合法 Queued 事件。

没有工作时，阶段不必产生实际队列节点或调用组件，但逻辑阶段游标仍单向推进。阶段已经越过后不得重新打开，即使它当时为空。每次推进到新的更大时刻，阶段顺序重新从前态观察开始；冷启动首时刻如何建立初始事件另由初始化契约规定。

六阶段不意味着每个时刻都要扫描全部组件；只评估具有合法激活的组件，并保留必要的全局提交协调。固定阶段顺序可以减少同刻调度复杂性，但不能保证 handler 自身循环终止，仍需独立诊断策略。

### 5.5 同刻业务案例

| 场景 | 到期收集 | 候选评估 | 仲裁与提交/结果 |
|---|---|---|---|
| 内存服务到期 | 登记已满足计时 | 使用前态响应空间判断候选 | 有空间则本拍提交，不额外加一拍 |
| Credit 返回可见 | 登记返回事实 | 本拍不能使用这份新额度 | 提交增加额度，安排下一发送边沿评估 |
| 链路预定发送结束 | 登记区间结束 | 已有消息/credit 可竞争接续 | 本拍结束并接续，不借新释放的队列槽 |
| 源消费与最终 deadline 同刻 | 正常收集 | 仅消费前态接收队列中的响应 | 先提交完成，再检查 deadline，未清理的检查也不误报 |

取消边界例子：同刻“候选评估”事件 A/B 在阶段入口一起 Selected，A 无法取消尚未调用的 B；A 若按已定义动作权限取消尚未开始“结果检查”阶段中的 Queued 动作 C，则可以移除 C。阶段锁定只规定允许操作的时间窗口，不授予任意取消业务责任的权限。

示例：恢复切点为 100 ns，服务到期为 140 ns。内核直接装载 `now=100 ns`、事件截止 `140 ns`；若没有更早动作，下一次推进到 140 ns。不等待宿主 40 ns，也不从模拟时间零重新运行。

## 6. Checkpoint 与装载

采用一个权威逻辑时间，取消原 SystemC 相对时间加恢复基点的需求。

候选快照内容：

- 逻辑切点、阶段、两个时钟的参数和累计状态。
- 组件、事务、payload、队列及资源账本。
- 有效事件与其稳定顺序、句柄版本及必要的动作状态。
- 各类下一身份/序号、输入游标、随机状态、累计统计。

装载时重建组件注册表和可索引堆：载入有效记录，按原排序键建堆，再为每个节点生成位置索引并验证双向一致性。不恢复宿主栈、线程、函数指针或堆内部数组布局，也不把旧 heap_position 当持久句柄。

主动取消的记录无需作为堆节点保存；但仍有活动使用者依赖的控制记录不能提前回收，也不能将其误恢复为 Queued。C48 允许在最终责任及使用者结束后移除记录；之后旧句柄解析明确失败，不要求恢复无限终态历史。

C47 要求保存各编号分配器的下一编号/已分配上界，不能从活跃对象最大 ID 重算。当前版本、原入队排序、下一排序序号以及仍有责任的事件引用不能漏存；恢复建堆不分配新的模型 ID 或替换原排序。

快照保留有效对象与其责任/引用关系，以及仍有使用者的终态对象；已回收对象无需重建。具体所有权计数可保存或由权威关系重建，但必须验证引用目标与业务责任一致，不能直接保存宿主引用计数当作完整恢复方案。格式仍归 Q7。

组件业务事件与激活有不同责任：业务事实是权威，C42 的最早激活是调度摘要，不能把激活本身当成第二份到期/交付动作。需覆盖所有尚未处理事实、最早待激活切面与句柄、后续需求，以及有效版本/排序序号。摘要是否显式保存或唯一重建仍待冻结；重建不能重新分配排序序号而改变规范化轨迹。

周期服务保存原始截止点、不重置相位；提交后保存时，该时刻提交前采样若已经完成，恢复不能再采一次。保存已提交输出前缀/采样进度的具体格式归 Q8。

先解析并校验全部引用与不变量，再允许任何事件执行。C43/C46 将合法业务切面放在提交与结果检查之后的保存边界，不保存一半执行的 handler。应校验前五阶段已完成，不残留未处理业务 Selected 批次或可重开的过去阶段；不能将 Selected 动作恢复为可取消的 Queued 来改变行为。

第六阶段中保存协调动作本身的消费/继续位置、同刻多个保存申请的合并及输出前缀提交方式仍属 Q6/Q8 余项，不能因为六阶段已定就假定文件协议已定。恢复记录必须能判断本时刻前五阶段已处理，不能重跑前态采样、完成计数或 timeout 检查。

共享响应池中“正在发送”的槽位、发送后仍在 CDC 中的远端配额、已提交写和已固定读值仍按原契约保存。换内核不减少这些必须保存的业务状态。

快照格式、版本兼容、失败政策及具体安全切面仍归 Q6/Q7；本次路线选择不表示已批准任意配置变更后恢复。

## 7. 验收与性能边界

先验证小型解析轨迹与内核负测，再接入现有双域/credit/内存恢复矩阵。

- 时间不倒退，非法时间/阶段与溢出明确失败。
- 事件取消、重调度及宿主内存复用不会使旧句柄命中新对象或双重释放，模型 ID 不复用。
- 同刻双域候选评估不因注册顺序改变资源分配。
- A 连续、B 保存后继续、C 新进程恢复的规范化后缀一致。
- 跳过空闲周期版本与朴素逐边沿参考在相同契约下结果一致。
- 堆删除/改期的索引保持一致，重建不改变有效事件顺序。
- 多原因激活合并不丢业务动作、不漏下一拍提醒。
- 周期采样不延后精确动作，恢复后周期相位不变。
- Selected 后取消/改期被拒绝，完成与已 Selected 的最终超时检查同刻仍判成功。
- 真改期更新版本/顺序，无变化改期完全保留；最早激活能逐次重建后续需求。
- 提交前周期样本、提交后 checkpoint 和时间积分分别核对，不重复采样/累计。
- 阶段入口整批 Selected，同阶段互取消均被拒绝，后续阶段合法 Queued 操作不被过早锁定。
- 禁止当前/过去阶段追加，无空阶段重开、无隐式 1 ps 修正；后续合法阶段无需多等一个时刻。
- 最后使用者释放前不回收，责任独立转移后不强留无关父对象；恢复保持所有权与编号分配上界。

移除 SystemC 只是减少一层状态和时间协调，不自动保证更快。需测量每完成事务派发数、候选评估次数、峰值队列、取消/改期频率、索引维护成本、wall time、快照暂停和恢复成本。不要将模拟吞吐与宿主执行速度混用。
