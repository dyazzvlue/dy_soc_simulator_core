## 2. 有理数时钟

### 2.1 表示与边沿计算

逻辑时间采用整数 ps，纯 C++ 内核时间分辨率为 1 ps；C36 仅替换时间管理实现，不改变原量化规则。频率、周期与边沿序号不能通过每拍浮点累加维护。

以周期为既约正有理数 `P/Q ps`、整数 ps 相位 `phi` 为例：

```text
ideal_edge(k) = phi + k * P / Q
edge(k)       = phi + ceil(k * P / Q)
```

这里 k 为相对于原始时钟原点的非负边沿序号；`k=0` 是相位位置，是否在该边沿允许冷启动发射由初始化契约决定。整数相位是本文公式的示例前提，最终配置是否允许有理数相位仍待确认。

可通过商/余数累积实现相同结果，也可从边沿序号精确计算；两者是等价表示，不要求把所有派生字段都存成独立权威状态。乘法、加法、向上取整和向内核 tick 表示转换都需溢出检查，不能先溢出再比较。

若频率输入为有理数 `f_num/f_den Hz`，周期为 `10^12 * f_den/f_num ps`，约分和范围检查也必须采用精确整数运算。

### 2.2 3 GHz 例子

令 `phi=0`、`P/Q=1000/3 ps`：

| k | 理想边沿 ps | 量化边沿 ps | 与前一量化边沿的间隔 ps |
|---|---|---|---|
| 0 | 0 | 0 | — |
| 1 | 333 1/3 | 334 | 334 |
| 2 | 666 2/3 | 667 | 333 |
| 3 | 1000 | 1000 | 333 |
| 4 | 1333 1/3 | 1334 | 334 |
| 5 | 1666 2/3 | 1667 | 333 |
| 6 | 2000 | 2000 | 333 |

在上述整数相位前提下，每个边沿满足 `0 <= edge(k)-ideal_edge(k) < 1 ps`，不会逐周期积累漂移。这是离散时间量化，不是物理 jitter 模型，也不承诺分辨亚 ps 的先后顺序。

从边沿 k 开始、持续 N 个周期的动作在 `edge(k+N)` 到期，不使用 `edge(k) + N*ceil(P/Q)`。例如从 k=1 持续 2 周期，到期为 1000 ps，而不是 1002 ps。

### 2.3 表示范围仍需冻结

建议首版要求周期至少 1 ps，拒绝会使同一时钟多个边沿压在同一 tick 的更高频率；这项配置限制尚未获确认。不能静默合并重复边沿。

还需冻结频率/相位输入语法、最大时间和序号范围、整数宽度、配置越界诊断。若允许非整数 ps 相位，必须扩展精确公式及恢复契约，不能先把相位截断。

## 3. 同刻状态可见性

### 3.1 共同逻辑切面

C44–C46 已确认同一逻辑时间 t 的六阶段语义；具体枚举名/编码与 API 后定：

```text
前态观察（先积分结算，再按需只读采样）
 -> 到期收集（形成事实，不提前修改可见资源）
 -> 候选评估（各到边沿时钟域共用同一前态）
 -> 仲裁与提交（先完整裁决，再统一更新）
 -> 结果检查（完成优先，再检查最终 timeout）
 -> 保存边界（协调合法 checkpoint 申请）
```

到期条件可以参与本拍评估，例如已预定的服务计时到期；不能在“收集”时提前修改可用 credit 或队列可见性。这套逻辑 phase 由纯 C++ 内核协调，不要求兼容通用 HDL delta-cycle。

两个域恰好同刻到边沿时，都依据同一提交前切面决策；不能先执行内存域后让源域读取刚提交结果。颠倒宿主回调注册顺序必须保持结果不变。

每个阶段入口一次性将该阶段所有待执行事件转为 Selected，再执行处理；后续未开始阶段仍 Queued。禁止新增或改期到当前/已结束阶段，不生成同阶段追加批次，也不静默加 1 ps。允许合法后续阶段动作不等于允许消息或 credit 同拍旁路。空阶段不必产生实际队列节点，但一旦逻辑越过就不能重开。详见 [09 的阶段规则](./09_discrete_event_kernel.md#5-时间推进与同刻提交)。

### 3.2 可见性表

| 本拍发生的事 | 本拍允许 | 必须等下一本域边沿 |
|---|---|---|
| CDC 完整消息可见 | 登记进接收队列 | 消费、启动服务或转发该新消息 |
| Credit 返回可见 | 增加发送侧已知额度 | 使用该新额度发送 |
| 等待队列/服务槽/响应槽释放 | 提交释放及必要返回动作 | 用该刚释放槽位接纳新占用 |
| 更早冲突请求执行提交 | 更新 RAM、固定读值、解除依赖 | 启动因此才变为可执行的年轻请求 |
| 已启动服务在本拍到期 | 若边沿前已有响应空间，可提交 | 不额外因到期通知等待一拍 |
| 已预定整消息发送在本拍结束 | 下一条已排队且 credit 充足时，可无缝接续 | 若只能依赖本拍新消息/新 credit，则仍需等待 |

同拍启动与提交可以共存，但启动不得借用提交刚释放的服务槽。允许接续链路占用区间不是允许本拍释放的任意队列槽旁路。

源端的“收到响应并完成”落实为消费接收队列中的响应并匹配事务；CDC 入队本身不是完成。C32 已确认每源消费宽度独立可配置为正整数，默认每源每边沿 1 条，且只消费边沿前已有响应。

## 4. 事务级 CDC

每条消息按以下路径交付：

```text
发送域整消息传输结束
 -> 可选数据传播延迟（是否独立配置尚待确认）
 -> 严格更晚的第一个接收域边沿
 -> 接收域同步级数
 -> 整消息在有限接收队列中可见
 -> 下一接收边沿才可使用该新消息
```

即使传输结束恰好命中接收边沿，也不能在该边沿采样。Credit 返回同样跨到原发送域，不是释放槽位时立即增加发送者额度。

**已确认 C31：**同步级数为正整数 `S>=1`；严格更晚的第一个接收边沿为第 1 级，第 S 级边沿提交为可见。如果输入可采样时间为 a：

```text
j = min { k | receiver_edge(k) > a }
visible_time = receiver_edge(j + S - 1)
```

S=1 在第一个严格更晚边沿可见，S=2 在再下一个边沿可见；不能在公式外无意再加 S 拍。可见后下一拍使用是独立的 no-bypass 规则。

此模型不模拟 Gray pointer、双触发器内部电气过程、逐 bit 亚稳态或概率故障；S 是事务级延迟抽象。链路占用、传播和 CDC 三段分别计时，不重复计算。

**已确认 C33：**多条完整消息在同一接收边沿变为可见时，批量登记全部已获得接收 credit 的到期消息，按该方向的实际发送序号排序。目标按此顺序分配接纳序号，各源响应接收 FIFO 保持对应子序列。发送序号及下一序号必须可恢复，不能用宿主回调顺序代替。

批量登记不新增“每边沿一条”的 CDC 出口排队级，也不新增 credit；到期消息数受既有配额限制。它不表示可以同拍消费新消息，更不提高每内存边沿最多启动一笔的服务宽度。控制返回记录仍须逐份记账，不能因合并通知丢失或重复额度。

## 5. Deadline 与固定宽限期

### 5.1 已确认规则

对一笔事务，令原 deadline 为 D，源/互连域边沿为 `source_edge(k)`，宽限周期数为非负整数 G：

```text
G = 0：final_deadline = D
G > 0：j = min { k | source_edge(k) > D }
       final_deadline = source_edge(j + G - 1)
```

- 原 deadline 后严格更晚的第一个源域边沿算第 1 个。
- 宽限只给一次，零散进展、credit 返回或恢复进程不能重置或延长窗口。
- 最终时刻先提交正常完成，再检查仍未完成的事务；恰好完成算成功。
- 超时是报错终止与现场诊断，不自动取消事务、归还 credit、回滚已提交写或伪造错误响应。
- `D < completion_time <= final_deadline` 属于宽限内完成，单独统计；真实 latency 不截断。
- 恰好在 D 完成不算超出原 deadline。

原 deadline 的计时起点、时长和单位、G 默认值仍待确认；例如“从源接纳开始计时”目前只是候选，不是既定规则。

C52 已确认超时检查持有原事务的 OwnerRef，事务保存检查的弱句柄。若检查未取消，即使源已消费响应并移除 outstanding，原事务仍可供检查读取已提交完成状态；检查结束不重复计数。合法取消或执行结束后按 C48 解除拥有责任，Selected 锁定和超时诊断终止政策不变。该关系必须随 checkpoint 恢复。

### 5.2 边界例子

教学源域边沿为 0、1000、2000、3000、4000 ps：

| D ps | G | 最终检查 ps | 解释 |
|---|---|---|---|
| 2000 | 0 | 2000 | 不追加宽限 |
| 2000 | 2 | 4000 | 3000 为第 1 个，不把 D 所在边沿算进去 |
| 2500 | 2 | 4000 | 3000 为第 1 个，4000 为第 2 个 |

若最终检查为 4000 ps，源端恰好在 4000 ps 完成则成功；仅响应入队而尚未消费，不算完成。D 不在边沿上也要按逻辑时间处理，不能无说明地四舍五入。

### 5.3 与 watchdog 的区别

每事务 deadline 限制单笔责任的最长等待。全局无进展 watchdog 用来发现系统长时间不前进，两者不能互相替代；其他事务持续完成不应无限延长这一笔事务的窗口。watchdog 阈值和启用策略尚未冻结。

建议诊断至少包含事务当前阶段、阻塞资源、D/G/最终时刻、两域边沿状态及待执行动作。诊断格式归 Q8。

## 6. Checkpoint 要求

- 两个时钟保存原始相位、有理数周期，以及边沿序号或等价余数权威状态；恢复不从切点重新起算周期。
- 动作保存起始/到期边沿或可唯一重建的绝对逻辑时刻；不把完整服务时长重新等待一次。
- CDC 保存消息、方向、所属配额、发送序号、采样/可见时刻或可唯一重建的同步进度；保存每方向下一发送序号。
- Timeout 保存原 D、G、最终边沿/时刻及宽限状态，恢复不得重新赠送 G 拍。
- C46 将合法业务切点放在同刻所有时钟域提交与结果检查后的保存边界，不能只保存一半时钟域。具体触发、申请消费与失败策略归 Q6。
- 业务事件与派生唤醒区分权威来源，恢复不能重复安排 CDC、链路结束或最终 deadline。

详见 [恢复设计](./03_checkpoint_and_restore.md)。
