| C10 | 目标完成服务并实际执行时写入/取值；源收到响应才完成 | 已固定读值不因返回延迟重新采样；写可见可早于确认到达 |
| C11 | 重叠且至少一写的请求按目标接纳顺序执行 | 非冲突请求和重叠读可独立推进；不承诺源端程序序 |
| C12 | 长度为 1、2、4、8、16、32、64 B，按自身长度对齐 | 不支持掩码、非对齐或自动拆分，写 payload 覆盖全部请求字节 |
| C13 | 单 RAM 目标、地址 0 起、容量可配置、默认 1 MiB、冷启动全零 | 64 位物理字节地址；payload 按递增地址存放；无 MMIO/多区域 |
| C14 | 响应允许乱序，源端按事务身份匹配 | 不按源发出顺序退休；因果依赖显式等待前项完成 |
| C15 | 非法访问报错并终止运行，内部非法请求同样处理 | 接纳前校验，不模拟总线错误响应，不静默丢弃或部分写入 |
| C16 | 首版支持有理数频率，1 ps 逻辑时间网格，累计理想边沿向上取整 | 不用每拍浮点或量化周期累加；保存边沿序号/余数；C36 仅替换时间管理实现 |
| C17 | 首版端到端包含源/互连域与内存域 | 双域恢复从 P1 验收，不推迟到扩展阶段 |
| C18 | 事务级 CDC、有限接收缓冲和 credit | 传输后严格更晚接收边沿开始同步；不模拟逐 bit 亚稳态 |
| C19 | 边沿前状态决策、统一提交；新状态不旁路 | 新消息/credit/释放槽位/解除依赖下一本域边沿参与新决策；预定服务到期可本拍提交 |
| C20 | Timeout 原 deadline 后给一次固定源域周期宽限，最终时刻完成优先 | 严格更晚边沿起算，G=0 在原时刻检查；不滑动续期、不自动回滚或返资源 |
| C21 | 两源一目标，请求/响应独立带宽，每方向串行整消息 | 请求源域驱动、响应内存域驱动，可双向同时传输 |
| C22 | 消息级 RR；请求每源 FIFO 队首，响应按目标源最早就绪分组 | 跳过空组/无 credit 组，仅实际开始发送才推进指针；不承诺字节公平 |
| C23 | 冲突在启动服务前阻塞；挑最早接纳且可启动者 | 尊重所有更早未提交冲突，可跳过阻塞请求服务无关地址 |
| C24 | 服务启动不预留响应槽；到期响应满则占服务槽等待 | ready-but-uncommitted 时写不更新、读不取值，不隐藏缓存结果 |
| C25 | 按 bytes/发送域周期计时、完整消息交付、每消息一 credit | 读请求/写确认计头部；写请求/读响应计头部加数据；占用周期向上取整 |
| C26 | 独立有延迟的 credit 控制返回，经过 CDC | 请求等待槽在启动服务释放；响应接收槽在源消费释放；返回可见后下一发送边沿使用 |
| C27 | 读写独立固定服务周期、有限服务槽与启动间隔 | 每内存边沿最多启动/提交各一笔；有响应空间且已到期者中最早接纳者提交 |
| C28 | 预定整消息发送结束边沿可无缝启动下一条 | 不人为插入空拍，但下一条须使用边沿前已有消息及 credit；不旁路新返回资源 |
| C29 | 目标待发响应使用共享总池，按源维护逻辑 FIFO | 任一源可使用全部空闲容量；不提供每源容量隔离 |
| C30 | 本地响应槽保持到整条响应发送结束才释放 | 正在发送的响应仍占共享池槽，不额外增加发送暂存容量；刚释放槽下一内存边沿可用 |
| C31 | CDC 第一个严格更晚接收边沿算第 1 级，S 为正整数，第 S 级入队可见 | 可见后下一接收边沿使用；级数的默认值仍未选择 |
| C32 | 每源响应消费宽度独立可配置为正整数，默认每边沿 1 条 | 按本源 FIFO 顺序消费边沿前已有响应，完成匹配并发起 credit 返回 |
| C33 | 同边沿完成 CDC 的已授权消息批量入队，按该方向发送序号排序 | 不增加出口限速排队级；后续服务/消费宽度与 no-bypass 不变 |
| C34 | 读写服务延迟为正整数内存周期，k 启动，k+L 最早提交 | 不支持 L=0；响应满时等待空间，不重算 L |
| C35 | II 为正整数，按上一次实际启动边沿计数 | 上次 k 启动则下一次不早于 k+II；不是固定周期窗口，失败尝试不重置计数 |
| C36 | 首版改为纯 C++ 确定性离散事件内核，移除 SystemC 依赖 | 取代 C3；显式状态机/事件承载未来行为，不依赖挂起进程；保留 Q2–Q4 模型语义，不在首版承诺双后端 |
| C37 | 首版单宿主线程执行模型，多线程同步以后再按性能需要评估 | 不限制模型内部并发服务或多时钟域；首版不实现并行调度 |
| C38 | 统一周期仅用于采样、维护或明确的周期行为 | 精确业务事件不等待公共同步点；不采用局部超前后再交换结果的时间解耦 |
| C39 | 全局事件日历采用可索引最小堆，取消/改期主动移除旧记录 | 不采用惰性堆积；位置索引为派生状态，恢复时重建，逻辑身份与有效性检查仍保留 |
| C40 | 仅 Queued 动作可取消/改期，Selected 起锁定；最终事务超时保持诊断并终止 | 不新增超时取消事务后继续运行协议，不回滚已发生操作；同刻完成仍优先 |
| C41 | 实际改期保持 EventId，更新 version 和入队排序序号，返回新句柄 | 时间/阶段均不变则无操作，保留版本和顺序；旧句柄不能修改新版本 |
| C42 | 每组件只保留一个尚未派发的最早下一次激活 | 业务 timer/交付事实独立保存；处理后重新计算后续需求；Selected 期间新需求保留，不修改当前事件 |
| C43 | 默认周期诊断快照看本时刻模型评估/提交前状态 | 完成/超时结果与 checkpoint 保持提交后；队列平均占用用时间积分，不靠周期采样近似 |

### Q1 的候选方案

| 方案 | 能验证什么 | 增加的成本 |
|---|---|---|
| A：只读、仅时序元数据 | 队列、credit、吞吐、延迟及控制状态恢复 | 最小，但不能验证内存内容恢复 |
| B：读写、无真实 payload | 不同流量大小/方向、读写服务竞争 | 仍无法检查实际读值，不能称为完整数据正确性 |
| C：受限读写、真实 payload | 时序和数据闭环，内存与在途数据都可恢复验证 | 必须定义地址、读写可见性、冲突顺序和存储规模 |

用户已选择 C：受限读写与真实 payload。地址空间、访问规则和冲突顺序已由 Q2 确定；暂不引入 cache coherence、原子操作和虚拟地址。
