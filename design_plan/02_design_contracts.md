## 1. 组件与扩展契约

| 编号 | 拟定要求 |
|---|---|
| MOD-01 | 每个组件声明配置、输入动作、输出动作、持久状态和资源责任。 |
| MOD-02 | 影响未来行为的状态必须显式保存或有唯一、确定性的重建规则。 |
| MOD-03 | 构造、装载、引用解析、验证、启动分离；构造及装载不得自动注入业务。 |
| MOD-04 | 业务 handler 本次处理后返回；跨时间等待由显式状态和动作表示，不依赖挂起线程栈或协程帧。 |
| MOD-05 | 组件必须声明 checkpoint 能力；不支持的系统组合应拒绝保存，不能漏存。 |
| MOD-06 | 相同接口的不同精度模型不自动具有状态互换能力，须另行定义迁移契约。 |

首版建议静态注册组件类型，不优先设计动态共享库插件系统。逻辑职责分层优先于继承层次和类数量。

以后允许第三方适配器，但适配器必须覆盖被包装模块中所有影响未来的状态、定时器及外部责任。仅包装收发端口不构成 checkpoint 支持。

## 2. 时间与同拍语义

| 编号 | 拟定要求 |
|---|---|
| TIME-01 | Q3 已选 1 ps 整数逻辑时间网格，C36 改由纯 C++ 内核维护；转换、负值和溢出必须检查。 |
| TIME-02 | 组件通过统一时间服务读取逻辑时间；恢复直接装载逻辑切点，不以宿主时间或另一个调度器时间作为权威。 |
| TIME-03 | 首版两个时钟域，采用有理数周期累计边沿向上取整；保存原相位及边沿序号/等价余数，恢复不重新对齐。 |
| TIME-04 | 边沿前状态决策、统一提交；新消息/credit/释放槽位/解除依赖下一本域边沿才可使用；同刻双域不依赖注册顺序。 |
| TIME-05 | 不允许向已过去的逻辑阶段安排动作；零时间连锁必须有终止诊断。 |
| TIME-06 | 空闲跳过和批处理只能省去无模型影响的工作，必须保留定时与周期副作用。 |
| TIME-07 | CDC 从严格更晚的接收域边沿计第 1 级，第 S 级入队，S 为正整数；可见后下一接收边沿使用。同边沿到期消息按方向发送序号批量登记。 |
| TIME-08 | Timeout 追加一次固定源域周期宽限；最终时刻完成优先，恢复不重置窗口，超时不自动回滚/返资源。 |
| TIME-09 | 已预定服务到期可本拍提交；已预定链路结束可无缝启动下一条，但须使用边沿前已可用的消息和 credit。 |

候选阶段组织为“收集到期条件、冻结边沿前状态 → 评估候选 → 仲裁/预留 → 统一提交 → 完成/超时诊断、观测/保存边界”。收集不等于提前登记新资源。Phase 编码与阶段内新动作处理仍待冻结；纯 C++ 内核不照搬通用 HDL delta-cycle 语义。

Q3/Q4 已确定上述行为、消息级 RR、CDC 计数及同刻批量接纳。P0 仍需冻结相位/范围、初始化与数值基线；不能重新将已确认的 no-bypass 或固定宽限当作任意实现选择。

确定性 tie-break 不能替代仲裁政策。C37 已确认首版单宿主执行线程，暂不设计并行候选提交。C38 的统一周期不是业务屏障，不推迟精确动作；C43 默认周期诊断快照在评估/提交前读取，周期结束策略仍归 Q5。

## 3. 事件与身份

**EVT-01：**可恢复事件记录至少说明逻辑到期时间、阶段、稳定排序信息、动作类型、目标组件身份、必要事务身份和 payload 引用。

**EVT-02：**序列化记录不得以裸指针、闭包地址、宿主文件描述符或栈位置作为身份。共享引用恢复后仍应共享，独占对象不能因内容相同被错误合并。

**EVT-03：**区分组件代际、事务身份复用和事件重调度有效性。可以合并编码，但不能遗漏任一失效范围。

**EVT-04：**取消事件不自动完成事务，也不自动释放其全部资源。C39 选择在可索引堆中主动移除旧记录，取消后按事件所有权释放引用；不得删除其他事务/队列仍持有的 payload。C40 只允许 Queued 取消/改期，Selected 起锁定；事务最终超时仍诊断并终止，不新增取消协议。

**EVT-05：**组件激活通知与业务动作记录分离。C42 每组件只保留一个尚未派发的最早下一次激活；业务事实逐条保存，处理后重算后续激活。Selected 期间的新需求转入后续状态，不修改当前事件，也不能被当前处理清掉；不同阶段仍分别处理。

**EVT-06：**未来动作只能有一个权威来源：显式事件表，或组件状态中的明确重建规则。不能保存一次、恢复时又由组件重复安排一次。

**EVT-07：**C39 已确认全局可索引最小堆；Queued 有效动作与堆位置索引双向一致，每次删除/交换均维护索引。堆位置不能作为持久句柄，恢复按事件身份和排序键重建。

**EVT-08：**C41 实际改期保持 EventId，增加版本与入队排序序号并返回新句柄；时间和阶段均不变的合法改期不更新。先校验有效句柄与 Queued 状态，旧版本不得修改新安排。

身份复用/编码、错误枚举、选取批次、激活保存表示及阶段内新增动作处理仍待确认。纯 C++ 内核、逻辑句柄与组件分派方案见 [09](./09_discrete_event_kernel.md)。

## 4. 事务与资源

| 编号 | 拟定要求 |
|---|---|
| RES-01 | 明确 generated/offered、accepted、active、succeeded、failed/aborted 的边界；首版支持哪些终态待确认。 |
| RES-02 | 已接纳事务必须有唯一终结结果，或在结束报告中明确仍在途，不能静默消失。 |
| RES-03 | 每个队列、tracker、credit 池有单位、容量、持有者和释放条件。 |
| RES-04 | 发送许可、预留和实际传输不能重复扣减；并发候选不得重复使用同一份资源。 |
| RES-05 | Credit return、响应到达、上层完成分别定义，不因编码方便合并。 |
| RES-06 | 反压时保留请求或执行明确的拒绝契约；有限硬件不能靠无限宿主容器规避容量限制。 |
| RES-07 | 服务 latency、启动间隔、并发容量分开配置，避免仅有 latency 的无限服务模型。 |
| RES-08 | 请求/响应独立带宽，按字节计时、整消息交付；每消息一个接收 credit，发送成功才推进消息 RR。 |
| RES-09 | 请求 credit 保护目标等待队列，启动服务释放；响应 credit 保护各源接收队列，源消费释放；经独立控制延迟及 CDC 返回。 |
| RES-10 | 最早接纳且可启动者获得服务；启动前等待所有更早冲突请求提交，允许跳过不具资格请求服务无关地址。 |
| RES-11 | 服务开始不预留响应槽；到期响应满则保持未执行并占服务槽，不能隐式缓存结果。 |
| RES-12 | 每内存边沿至多启动/提交各一笔；提交选择已到期且有响应空间的最早接纳者。 |
| RES-13 | 本地响应共享总池，按源逻辑 FIFO；提交占槽，整消息发送结束释放，正在发送者仍计入总容量。 |
| RES-14 | 每源响应消费宽度为独立可配置正整数，默认 1；消费边沿前的 FIFO 响应并逐条匹配、释放接收槽。 |
| RES-15 | Lr/Lw/II 为正整数；k 启动则 k+L 最早提交，下一启动不早于 k+II；II 按实际启动更新，不使用固定周期窗口。 |

在对应模型边界检查：

```text
accepted = active + succeeded + failed + aborted
free_resource + allocated_resource = capacity
```

单接收池的教学配额可用 `C + F + Q + R = capacity` 检查，其中 F 为已授权在途，R 为释放后返回在途。若有独立预留、分块或合并，必须调整账本，不能机械沿用公式。

已确认的 [Q2 数据契约](./06_memory_transaction_contract.md)补充如下：

- MEM-SEM-01：目标实际执行提交时写入或固定读值；源收到响应后才端到端完成。
- MEM-SEM-02：字节区间重叠且至少一写时，按目标接纳顺序执行；非冲突请求允许独立推进。
- MEM-SEM-03：长度仅为 1、2、4、8、16、32、64 B，按自身长度对齐；无掩码、非对齐或自动拆分。
- MEM-SEM-04：单区域 RAM 从地址 0 开始，容量可配置、默认 1 MiB，冷启动全零；64 位地址必须防溢出检查。
- MEM-SEM-05：payload 按递增地址排列为字节序列；响应允许乱序，以稳定事务身份匹配；依赖请求显式等待。
- MEM-SEM-06：非法访问在源接纳前报错并终止，内部发现非法请求亦终止；不模拟总线错误响应，不部分写入。

本模型不承诺源程序序或 ISA 内存模型。冲突已在服务启动前门控；服务到期但共享响应池无空间时仍未执行。响应池容量数值仍待确认，不能把“到期”误记为“已提交”，也不能漏算正在发送者占有的本地槽。

## 5. 输入、输出与统计

**OBS-01：**所有随机源使用显式流身份并保存其状态；可复现运行需固定算法和输入。不能仅存 seed 而忽略已消耗的随机位置。

**OBS-02：**trace 输入保存内容身份与游标；首版建议仅使用受控离线输入，不接实时网络或不可回滚的外部设备。

**OBS-03：**规范化 trace 保留时间/阶段、事务与组件身份、关键事件和资源变化。宿主地址、wall time 等单列为诊断，不参加模型轨迹等价比较。

**OBS-04：**吞吐说明方向、字节/消息单位和时间窗口；延迟说明起终边界和 cohort；队列占用采用时间积分而不是事件次数平均。

**OBS-05：**统计 reset 不得清模型状态。保存累计面积、最后结算时间、ROI 和跨窗事务信息；恢复后不能重复累计。

**OBS-06：**恢复后的输出建议写新运行目录，并绑定父 checkpoint/trace 前缀，避免覆盖或重复追加旧输出。文件名与目录 schema 待 Q8。

**OBS-07：**C43 默认周期诊断快照只读本时刻模型评估/提交前状态；完成与超时结果在提交裁决后结算，checkpoint 保持统一提交后安全切面。时间积分先以旧占用结算上一段，再使用提交后占用开启下一段；恢复不重复采样或累计。

## 6. 错误与工程约束

- ENG-01：非法配置、容量溢出、重复完成、坏快照、不兼容输入必须明确失败；禁止饱和计数或默认成功来隐藏错误。
- ENG-02：区别正常排空结束、达到仿真上限、无进展、模型不变量失败；事件队列空但仍欠事务不能报告成功。
- ENG-03：无进展超时是诊断线索，不自动证明死锁；需要报告等待资源和依赖。
- ENG-04：测试区分解析结果/独立参考、模型不变量和恢复等价，避免只用同一实现自证。
- ENG-05：首版移除 SystemC 依赖；建议 C++20、CMake，具体工具链、测试库、配置解析库和序列化库须另行确认。
- ENG-06：新增组件必须提供配置负测、资源测试和中间态恢复测试。普通性能优化需通过同语义轨迹对照。
- ENG-07：跨版本快照迁移、任意旧模块直接接入和任意线程栈恢复均不作为默认能力。
